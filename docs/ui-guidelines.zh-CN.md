# 界面规范

[English](ui-guidelines.md) | 简体中文

Viva 现有界面的视觉和交互规则，从 `src/renderer/styles.css`、`island.css`、`personal.css` 与 `src/renderer/view/` 提取（2026-11-03，main `27de6f4`）。本文与代码不一致时以代码为准，同时修正本文；新界面照本文做。开发约定（分层、DOM、国际化、验证）见 [AGENTS.md](../AGENTS.md) 的「前端」一节，她的形象和状态见 [下面的「她的形象」](#她的形象)。

## 基调

代码里的名字是「A 方案 · 工业饱和 Bento · 深海蓝」：

- **只有深色**。`color-scheme: dark`，没有浅色主题，也不跟随系统切换。
- **一个强调色**。蓝调深底，搭一个亮蓝 `--accent`。橙和红只在出现状态时使用，平时界面上看不到。
- **平面、几何**。层次靠底色深浅和 1px 描边区分。阴影只给浮起来的东西（菜单、提示、toast、展开的岛）。不用渐变底，不用毛玻璃：`backdrop-filter` 会让背后每次重绘都卡顿，所以遮罩用半透明纯色。
- **米白只代表她**。她的素材自带米白底（`--maid-paper`），所以她的圆底就是这个米白，裁成圆形也看不出方边。界面其他地方不用米白，就像橙色只表示在等你一样。

## 颜色

全部在 `styles.css` 的 `:root` 里定义。只用 token；需要新颜色时先加 token，写清用途。

| token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#060B16` | 窗口底色；输入框（`.field`）内部也用它，比所在卡片低一级 |
| `--panel` | `#0D1526` | 卡片、输入区、图标按钮 |
| `--panel-2` | `#111B30` | 菜单、标签组底、悬停行 |
| `--raised` | `#15203A` | 浮起的小块：chip、badge、提示、toast、代码块 |
| `--line` | `#1B2742` | 默认描边、分隔线 |
| `--line-2` | `#263557` | 强一级描边：次要按钮、菜单边、悬停后的边 |
| `--ink` | `#EEF3FF` | 主文字 |
| `--ink-2` | `#A3B0CC` | 次要文字、未选中的控件 |
| `--ink-3` | `#7686A6` | 说明、元信息、占位符、禁用项 |
| `--mute` | `#3C4A68` | 最弱的标记（轮次刻度等） |
| `--accent` | `#5AA9FF` | 可操作、选中、焦点、完成 |
| `--orange` | `#FF8A3D` | **等用户**：确认卡片、等待中的任务、上下文快满 |
| `--red` | `#FF4D5E` | 错误、危险操作 |
| `--white` | `#EEF3FF` | 发送按钮忙碌态的底色 |
| `--drawer-bg` | `#0A1120` | 对话旁边的抽屉 |
| `--island-bg` | `#070C18` | 岛（标题栏和桌面） |
| `--line-3` | `#2E3D5E` | 虚线和描边：空态、`.btn-outline` |
| `--user-line` | `#1F2C49` | 用户自己消息的边 |
| `--line-focus` | `#3A4C72` | 输入区聚焦时的边 |
| `--error-ink` | `#FF9AA4` | 错误文字 |
| `--maid-paper` | `#FAF7F2` | 她的圆底，别处不用（view/maid.ts） |

颜色的语义固定，不同位置要一致：

- **蓝 = 你可以点 / 已经好了**。主按钮、选中的标签、焦点环、`data-tone="done"`。
- **橙 = 在等你**。在岛的边和圆点、她的描边、确认卡片的边和脉冲点，以及 `.btn-primary` 上出现。橙色按钮只用在「等用户决定」的卡片里，一般页面的主操作用蓝色 `.btn-accent`。
- **红 = 出错了**。边框、左侧 3px 色条，或 `color-mix` 调出的淡底色。错误文字用 `--error-ink`，直接用 `--red` 写字对比度不够。

透明度变体从 token 混出来，例如 `color-mix(in srgb, var(--accent) 12%, transparent)` 或 `color-mix(in srgb, var(--orange) 16%, var(--panel))`，不写 `rgba(90, 169, 255, .12)`。阴影用的黑色 `rgba(0, 0, 0, …)` 不在此列。

`test/renderer-css.test.ts` 会检查这些规则：`:root` 之外不能出现十六进制色值，强调色、橙、红也不能写成 `rgba`。代码高亮的 `.hljs-*` 是一组独立配色，例外保留。

## 字体

| token | 字体 | 用途 |
| --- | --- | --- |
| `--font-sans` | Space Grotesk → Noto Sans SC → PingFang SC → 微软雅黑 | 界面和正文 |
| `--font-mono` | JetBrains Mono → SF Mono / Cascadia Mono / Consolas → Noto Sans SC / 苹方 / 微软雅黑 → 通用等宽 | 路径、快捷键、密钥、代码、时间、模型名，中文使用明确的无衬线回退 |
| `--font-dot` | Doto | 点阵大字，只用在设置页的密钥状态 |

网页字体通过 Google Fonts 以 `display=optional` 加载，加载不到就用系统字体，不闪烁。CSP 只放行 fonts.googleapis.com 和 fonts.gstatic.com，新增字体也只能从这里来。

字号：

| 字号 | 用途 |
| --- | --- |
| 11px | 时间、快捷键、元信息 |
| 12px | `.label`、次要说明、chip、菜单附注 |
| 13px | 控件文字、菜单项、帮助文字、toast |
| 14px | 正文、字段、话题标题 |
| 15–16px | 按钮、输入框（输入框是 16px） |
| 22px | 卡片标题、提问、首页副标题 |
| 28px | 页面标题、确认卡片标题 |
| 48px | 首页问候语 |

- 字重用 400 / 500 / 700。600 用在列表里的标题（话题名、小标题），800 只配 Doto。
- 行高：正文 1.6，说明文字 1.7，标题 1.2–1.3，单行控件 1。
- `.label` 是正常大小写的小标题：无衬线 12px、500，不大写、不加字距、不用等宽。用 `view/dom.ts` 的 `label()` 生成。卡片标题、分组标题、菜单小节这类「当标题用」的小标签都一样：大写加字距的等宽字是模板式的外壳。等宽只给数据用，日期这类数据也不加字距。
- 12.5px、13.5px、14.5px 这类半号已经存在但不再新增，取相邻整数。

## 间距与圆角

间距大致以 2px 为步长。常用 `gap` 依次是 8 > 10 > 12 > 6 > 4。列表和控件组用 6–10px，卡片内部的区块用 14–16px，对话里的消息之间用 28px。

| 圆角 | 用途 |
| --- | --- |
| 2–3px | 细条、刻度、进度条 |
| 6–8px | badge、chip、小标签、`kbd` |
| 9–10px | 菜单项、标签、图标按钮、小按钮 |
| 12px | 按钮、字段 |
| 14px | 卡片、菜单、话题、代码块 |
| 16–18px | 空态、拖放区 |
| 20–22px | 输入区、确认卡片、首页卡片、密钥状态 |
| 999px | 胶囊：toast、回到最新、时间线上的工作目录 |
| 50% | 圆点、头像 |

嵌套圆角要同心：内层圆角 = 外层圆角 − 内边距。桌面岛上她的图就是这样对齐的（`island.css` 的 `.isl-face`）。`--radius-tile`（28px）定义了但目前没有使用。

## 布局

- **标题栏**：`--titlebar-h` 56px，岛高 `--island-h` 36px，在标题栏里居中。标题栏的岛只用状态色圆点。主进程 `window-options.ts` 的 `TITLEBAR_HEIGHT` 和这个值必须一致。
- **窗口按钮的留白**：macOS 左侧留 `--reserve-left` 84px 给红绿灯；Windows / Linux 用 `env(titlebar-area-width)` 算出右侧要让出的宽度。这个值只写在 `.titlebar` 上，避免窗口缩放时让所有消息的继承样式失效。
- **状态胶囊**：始终按整个窗口居中，空间不够时先收缩，不压到两侧按钮。
- **对话列**：`--col` 默认 760px，可以拖动边缘调整。左侧 `--rail-lane` 40px 留给轮次刻度。
- **抽屉**：`--drawer-width` 440px。窗口不超过 1100px 时浮在对话上方，不挤压对话。
- **断点**：720px（页面改单列）、760px（首页卡片竖排）、1100px（抽屉浮起）。窗口最小 880×600。
- **层级（z-index）**：

| 值 | 层 |
| --- | --- |
| 1–10 | 区域内部：拖动边缘 6、轮次刻度 9、下拉菜单 10 |
| 29–30 | 浮在内容上的菜单和它的遮挡层、窄窗口下的抽屉 |
| 32 | hub 页面（搜索 · 关于你 · 设置 · 后台 · 动态；动态不带侧栏） |
| 35 | 标题栏（岛向下展开时盖住对话） |
| 50 | 遮罩对话框 `.overlay` |
| 60 | toast、工作目录面板的遮罩 |
| 61 | 工作目录首次选择面板 |
| 90 | 拖入文件夹或图片时的全窗提示 |

新增层级时选一个已有档位，不要再插入新的数字。

### 桌面岛状态布局

尺寸由 `styles.css` 的 `--desk-*` token 定义，方向改变卡片定位，内部始终按头部、正文、操作区阅读。

| 状态族 | 尺寸 | 头像与内容 |
| --- | --- | --- |
| 圆形常驻 | 80px 命中框，72px 图像 | 头像独立居中，外侧透明，单层 1px 轮廓 |
| 状态轻提示 | 最宽 320 × 72px | 同一 72px 头像固定在独立 80px 命中区；提示位于旁侧，间隔 12px，后台计数为独立按钮 |
| 输入与内容卡片 | 440px 宽，最高 320px | 头像保持大小与桌面中心不变，标题、正文和操作区在旁侧面板中；靠右向左展开，靠下向上定位 |

确认、提问、引导、附件和后台列表共用内容卡片。长问题、附件及后台列表统一在正文区滚动，避免嵌套滚动。内容区支持键盘聚焦，文本选择与滚动区域各自响应指针操作。

一张卡片每句话只说一次。头部放状态圆点和状态名、旁边几个字的说明（用时、来自哪个任务、缺什么）以及图标；正文只写这个状态关于什么，不重复头部，没有更多内容的状态不画正文。每个动作只出现一次：下方已有按钮打开 Viva（查看回复、去 Viva 回答）时，头部不放 ↗；否则由 ↗ 打开 Viva。× 收起，与 Esc 相同。头部、正文和按钮在同一个面上，靠间距区分，不用分隔线或换底色的底栏。输入面板没有头部：↗ 和 × 放在输入框上方的状态条（助手正在做什么，或有请求在等）上，没有状态条时放在输入框右上角。话题名只出现在输入面板的去向行里，并且只在它能说明话题内容时显示，“你好”这类问候不会出现。请求被处理后（在岛上或在窗口里），卡片转到下一个等待的请求，没有则收起，并短暂提示“已处理”。未连接时点头像，卡片说明缺什么，并给出去设置的入口。桌面岛第一次停在桌面上时，显示一张操作说明卡，直到用户关掉。

主对话交给后台后，状态显示“后台执行中”。后台结束、等待结果回复时显示“正在整理结果”，回复结束后再显示“已完成”。请求确认、提问、停止和错误沿用各自的状态。

焦点在主对话，后台任务在设计上淡化：后台页是复杂任务需要细看时用的，一般任务用户可能从不打开。所以岛（标题栏和桌面岛）只显示正在执行和在等你的后台任务，展开的列表只列它们，计数也只数它们；做完的任务不在岛上计数，结果由主对话告诉你。结果送进你正在看的对话时，任务就算已读。后台页把做完的任务照常列在“已完成”里，只给 24 小时内结束、还没告诉过你的标“未读”（强调色），点开就算读过。

回合结束时，先用助手已提交的消息核对可见输出，再保存对话。本轮没有最终回复或达到输出上限时，保留已有内容，显示“未完成”，并在对话中解释原因。后台委派期间，任务执行和结果回传继续使用进行中状态。

从桌面岛发送新任务或补充要求后，主对话跟随最新输出，打开窗口时展示最新结果。用户主动向上滚动后保留其阅读位置。

悬停只反馈状态；短按头像统一展开或收起，主窗口通过“打开 Viva”进入。头像按下后固定抓取点，移动达到 8 个逻辑像素才拖动；释放后保持收起，Esc / 指针取消恢复原位。内容选择、滚动与按钮操作不移动岛。所有面板均可收起与 Esc，保留待办；收起不提交拒绝或跳过。位置菜单提供四角预设。

文字、文件引用、图片和错误按话题保存在同次运行的共享草稿中。明确新建话题时携带已准备的草稿，准备期间使用临时键，就绪后迁移到后端话题身份，迟到附件也随之重定向。返回已有话题或重载渲染器时恢复其自身草稿。窗口交接携带所有权代次，旧窗口回写会被拒绝。图片导入在切回 Viva 后继续完成，保留发起话题和剪贴板顺序。已排队的输入更新保留新产生的异步错误提示。新确认在输入面板上仅显示通知，输入框持续连接，保留焦点和输入法组合状态。明确点击才查看请求。单选提问明示点选立即作答。Enter 发送，Shift+Enter 换行，输入法组合期间保持选字语义。发送经主窗口接收回执后按版本清理，不能清除新输入。未连接时显示设置入口。

Windows 桌面岛在收起、展开和拖动时使用固定透明宿主与固定头像局部锚点；拖动只移动宿主，不缩小窗口，松手后保留头像命中区域直到新布局完成。透明宿主可以部分离屏，面板始终按实际显示器工作区避让边缘。其他平台先等待带版本的紧凑布局确认，再缩小拖动宿主，超时时保留完整宿主跟随。布局报告必须晚于排队的位置写入；布局版本变化后，过期或尚未就绪的确认不得替换原生命中区域。

## 组件

现有组件优先复用，不要另写一套相似的样式。

- **按钮 `.btn`**：46px 高、12px 圆角、15px / 700。再加一个角色类：
  - `.btn-accent`：蓝底，一般页面的主操作（保存、连接）
  - `.btn-primary`：橙底，等用户决定的卡片里的主操作（允许、确认）
  - `.btn-secondary`：透明底、1.5px `--line-2` 描边，和主操作并列的选项
  - `.btn-outline`：40px，1px 描边，列表和设置里的一般操作
  - `.btn-text`：无边框，最不重要的操作
  - 尺寸修饰：`.btn-small`（34px）、`.btn-field`（48px，与字段同高并排）
  - 一张卡片里只放一个实心主按钮，其他用描边或文字按钮。参考 `prompt-card.ts`。
- **图标按钮 `.icon-btn`**：40px（标题栏 36px），10px 圆角，`--panel` 底。必须带 `aria-label`。按下状态用 `aria-pressed="true"`，变成蓝边蓝字。
- **图标**：`view/icons.ts` 的 `icon(name, size)`，24 视图框、1.9 描边、圆端，颜色跟随 `currentColor`，`aria-hidden`。新图标加进 `ICONS`，保持同样的线条风格，不引入图标库。
- **字段 `.field`**：48px、12px 圆角、`--bg` 底、`--line-2` 边，聚焦时变成蓝边。默认用等宽字体（密钥、路径、模型名）；`textarea.field`、`select.field` 和个人资料自然语言字段使用无衬线字体。占位文字使用 `--ink-3`，opacity 为 1。多个字段并排用 `.field-row`。
- **开关**：原生 checkbox `.switch`，`accent-color: var(--accent)`。整行做成 `.pref-row` 的 label，标题和说明放在 `.pref-copy` 里。
- **分段选择 `.seg`**：选中项 `aria-pressed="true"`，`--raised` 底加粗。
- **标签页 `.tabs` / `.tab`**：选中项 `aria-selected="true"`，蓝底深字。
- **chip / badge**：`.chip` 28px、等宽 12px；`.badge` 20px、11px。都用 `--raised` 底。
- **菜单**：参考 `.ctx-menu`，`--panel-2` 底、`--line-2` 边、14px 圆角、6px 内边距；菜单项 `.ctx-item` 9px 圆角，悬停时 `--raised`。附加的快捷键用 `kbd`，说明用 `small`。
- **卡片**：`--panel` 底、`--line` 边、14px 圆角。需要用户处理的卡片换成 22px 圆角加状态色描边：确认卡片 `.confirm` 是橙边，首页的待办卡片是蓝边。
- **空态 `.empty`**：虚线边、16px 圆角、居中、13px `--ink-3`，说明这里会出现什么、怎么让它出现。
- **toast**：胶囊形，位于底部居中，最多带一个蓝色操作按钮。有遮罩或 hub 页面打开时改到顶部，避免盖住按钮。通过 `showToast` 弹出，不要每个页面自己写提示条。
- **遮罩对话框 `.overlay`**：`rgba(6, 11, 22, .82)` 纯色遮罩，不模糊；需要 `aria-modal`，Esc 关闭。
- **错误和提示**：表单下方用 `.form-error`（浅红）/ `.form-notice`（蓝），13px。说明文字用 `.help`。

## 状态写在属性上

状态通过属性表达，CSS 按属性选择，不另加 `.is-active` 这类状态类：

- 无障碍属性能表达的就用它们：`aria-pressed`、`aria-selected`、`aria-current`、`aria-expanded`、`disabled`、`hidden`。
- 其余用 `data-*`：`data-open`、`data-busy`、`data-status`、`data-form`，以及语气 `data-tone`。
- `data-tone` 已有的取值和颜色：`pending`（`--line-2`）、`working`、`waiting` / `waits`（橙）、`done` / `ok`（蓝）、`error`（红）、`full`（橙，上下文快满）、`quiet` / `off`（弱化）。新状态先看能不能归进这几类。
- `[hidden]` 全局是 `display: none !important`，组件不需要另写隐藏类。

## 阴影与动效

浮起程度（只给浮层用）：

| 场景 | 阴影 |
| --- | --- |
| 提示气泡 | `0 10px 28px rgba(0, 0, 0, .45)` |
| toast | `0 16px 40px rgba(0, 0, 0, .5)` |
| 菜单、输入区 | `0 20px 50px rgba(0, 0, 0, .5)`（输入区是 .45） |
| 展开的岛 | `0 24px 60px rgba(0, 0, 0, .6)` |
| 聚焦 / 拖入时的光晕 | `0 0 0 3–6px` 的 accent，透明度 .08–.18 |

动效：

- 悬停、透明度、小位移：0.1–0.15s。颜色、边框、阴影：0.3s。
- 标题栏岛的伸缩使用 `cubic-bezier(.3, 1.3, .5, 1)`，0.5s。桌面岛头像不做几何过渡，旁侧内容直接切换；拖动期间即时切换布局。
- 循环动画只用来表示「正在进行」「在等你」和「有结果还没看」：转圈、脉冲点、呼吸、打字光标、她的动图。三者各用一种节奏：转圈表示进行中；较快的向外脉冲表示在等你；最慢、原地明暗的呼吸表示有结果还没看，看过就停。她在哪里可以动，见[她的形象](#她的形象)。
- `prefers-reduced-motion: reduce` 时全局关闭动画和过渡。新增的循环动画仍要单独写一条 reduce 规则，在需要时给一个静止状态（例如呼吸停在 `opacity: .8`）。

## 她的形象

Viva 是一位蓝灰发、藏青制服的女仆。半身图使用 V7 Viva 配色版，并包含 V7.1 问候循环与 V7.2 完成动作；对话头像使用 V2.2 居中版。状态靠表情、动作和道具表达，不加浮层气泡。

**素材**在 `src/assets/maid/`。十种半身状态各有静图与动图，静图为 400×400，问候动图为 400×400，其余动图为 256×256。`avatars/` 保存十种专用对话头像，动静图均为 256×256。发行图采用质量 90 的不透明 WebP，背景为 `#FAF7F2`，与 `--maid-paper` 一致。每份清单记录基础交付提交、已确认的替换素材、源文件和发行图哈希、画布尺寸、逐帧时长与循环次数。半身问候每 1.98 秒循环，轮间停顿 720ms；对话问候只播一次。完成状态举起勾选卡并竖拇指，在高点停留 850ms，再回位，2.59 秒循环。其余状态循环，`listening` 复用 `ask`。

两组运行素材的合计预算为 4 MiB，单个动图上限 512 KiB、头像动图上限 128 KiB、静图上限 32 KiB，由 `test/maid.test.ts` 强制校验。发行内容包含运行图及其清单。复现命令为 `python scripts/optimize-maid-assets.py --output ../maid-runtime`，开发工具使用 Pillow 12.0.0 及其 libwebp 1.6.0。基础源对象固定于交付提交 `463fac186619fcf1bbdb8746035fc2fb21c168e5`，可通过 `git fetch origin 463fac186619fcf1bbdb8746035fc2fb21c168e5` 获取。已确认的问候与完成替换素材保存在 `build/maid-overrides/`，清单记录原交付哈希和播放参数。这些素材已用相同参数压缩一次；导出工具校验后原样复制，避免重复有损压缩。构建用的替换副本不进入发行应用。导出保留画布尺寸、帧顺序、时长和循环。

| 状态 | 姿势和道具 | 动图 | 描边 | 什么时候 |
| --- | --- | --- | --- | --- |
| `greeting` 问候 | 摆手后短暂停顿 | 半身循环，头像只播一遍 | 蓝 | 启动后第一次显示首页 |
| `idle` 待命 | 半身捧茶杯，头像眨眼待命 | 有 | 平静 | 没事的时候 |
| `thinking` 思考 | 半身握铅笔，头像托脸抬眼 | 有 | 蓝 | 收到问题、还没开始写 |
| `typing` 回答中 | 戴方框眼镜敲键盘 | 有 | 蓝 | 流式回答、调用工具 |
| `ask` 提问 | 半身扶耳罩，头像佩戴耳麦 | 有 | 橙 | 助手在问你 |
| `listening` 在听 | 同提问的图 | 有 | 蓝 | 文件拖到桌面岛上时；不在等你，所以是蓝色、不带角标 |
| `confirm` 需要你确认 | 半身夹板，头像摊手 | 有 | 橙 | 审批卡片、桌面岛 |
| `done` 已完成 | 半身举对勾卡并竖拇指，头像竖拇指 | 有 | 蓝 | 一轮结束、有准备好的事，还没看过。看过就回到待命：结束时窗口在前，动作播完一轮；否则等窗口回到前面再播一轮，或桌面岛上的结果卡片打开后关上。没人看时动作播两轮后停在静图，仍是已完成；桌面岛上头像外圈呼吸到看过为止 |
| `error` 出错 | 半身拿扳手，头像为难表情 | 有 | 红 | 回答失败 |

| `sleeping` 休眠 | 半身抱枕，头像闭眼呼吸 | 有 | 平静 | 目前不用 |

描边颜色和界面的状态色一致：橙表示在等你，红表示出错，蓝表示在工作或已完成。

由 `src/renderer/view/maid.ts` 绘制：

- **取景**：`whole` 是整张半身图，用于首页 200px、确认卡片 96px、桌面岛各状态 72px、动态详情 64px。`face` 使用 `avatars/` 中已居中的专用头像，用于对话 48px。两套均完整显示原画布。
- **动图**默认用于首页、确认和提问卡片、桌面岛及当前对话头像；动态列表和详情保持静图。系统开了「减少动态效果」时，使用对应静图。
- **对话里**只有最新一轮的回答旁边有她。之前的回答保留 48px 的空位、不放头像，这样她移到新回答时，上面的文字不会跳动。卡片在等你时她在卡片上，回答旁边不再重复。
- **桌面岛**收起和展开时都使用动图，同一布局与表情的刷新保留图片节点。状态不只靠文字和颜色，还用外圈的形状区分（`view/island-dom.ts` `deskSignal`）：
  - 头像外圈：处理中是转动的蓝色弧；需要确认、需要回答是带向外脉冲的橙色实线圈；已完成且还没看是呼吸的蓝色圈；出错是红色实线圈；未连接是灰色虚线圈，头像去色；没事时没有外圈，只留原来的细轮廓。头像本身不缩放、不降透明度，否则会发虚。
  - 状态旁的符号：确认「!」、回答「?」、完成「✓」、出错「×」、未连接「–」，处理中是一个小转圈。符号放在状态文字前，状态条的边框跟着状态变色。
  - 头像右下角的角标只在旁边没有状态文字、只剩头像时出现，文字在时由文字前的符号表达，不重复。
  - 空闲时只有头像，不留状态条：后台有任务在跑时才出现状态条，做完的任务不在头像上计数（见上文）。只剩头像、又有进行中的任务要计数时，件数挂在头像右下角（在头像的圆形区域内，点它打开后台列表）；它和状态角标都要显示时由件数占这个位置，状态由外圈表达。状态条的长度跟着内容走，最长 `--desk-peek-width`。
  - 系统开了「减少动态效果」时，外圈停在静止的样子。其他卡片保留已有角色角标。
- **首页**外圈多一道浅浅的「茶托」边，这是整个界面里唯一大胆的地方，别处不加。
- 第一次画她时预先加载全部静图，之后换状态不会闪出空圆。换表情时新图片解码完才替换旧的（`view/maid.ts` `showMaid`），不会空一两帧。
- 换图后，在首页、对话、确认卡片、动态详情和桌面岛上都看一遍，并连续切换几个状态。

## 无障碍与键盘

- 焦点环统一用 `:focus-visible`：2px `--accent` 描边、偏移 2px。如果元素自己画了焦点样式（轮次刻度、拖动边缘），才可以写 `outline: none`。
- 只有图标的按钮必须有 `aria-label`；装饰性图形加 `aria-hidden`。
- 状态变化需要读屏播报的区域用 `aria-live="polite"`：对话区、输入去向提示、toast。
- 自定义控件补全角色和键盘操作。例如拖动边缘是 `role="separator"` 加 `tabindex="0"`，方向键调整宽度，Home 恢复默认。
- 处理 Enter / Esc 之前先判断输入法：`event.isComposing || event.keyCode === 229` 时直接返回。
- 不关闭、不削弱 Chromium 的无障碍树（AX），性能问题另想办法解决。

## 文案

- 界面上的每一句话（包括 `aria-label`、`title`、占位符、空态和错误）都放进 `src/shared/i18n/messages/` 的中英两份资源。CSS 的 `content` 里不写文字；伪元素要显示文字时，由脚本把 `t()` 的结果写到属性上，再用 `content: attr(…)` 读出。拖入文件夹或图片时的全窗提示就是这样做的（`body` 的 `data-drop-hint`）。测试会检查这一条。
- 用口语说清三件事：**发生了什么、用户的东西怎样了、下一步怎么做**。例如：「这段内容太长，一次最多 20,000 个字符。请缩短后再发，原文已保留。」
- 不怪用户，不写错误码和堆栈，不说「操作失败」这种空话。
- 动作按钮用动词，并且和结果对得上（「从这里重来」「改了重发」「允许并安装」）。
- 链接和按钮的文字后面不挂箭头（「看全部」，不是「全部 →」），前面也不加「↗」这类符号。菜单路径保留箭头（「能力 → MCP」）。
- 标签和它说的内容之间不用中点拼接，用间距和更淡的字色分开：「本话题 2 条」、分组名后面跟数量、「用时 1 秒」后面跟「查看过程」。同一行里的数据（时间、地点）之间仍可以用中点分隔。
- 品牌名、工具和协议 id、路径、用户输入、模型输出保持原样，不翻译。

## 平台

两端用同一套界面，只有标题栏两侧的留白不同（见[布局](#布局)）。改动标题栏、岛或窗口尺寸时，macOS 和 Windows 都要看一遍；Windows 还要看 100% 和 150% 缩放。
