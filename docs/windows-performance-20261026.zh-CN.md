# Windows 对话响应与真实流式输出

[English](windows-performance-20261026.md) | 简体中文

历史验证日期：2026-10-26，Windows build 26200、175% 缩放。分支 `codex/windows-performance`，基线 `d6238c88fcdc9861d357b83005042a66830ecfe7`，包含 PR #45 和已合并的 PR #44。Electron 44.7.0、dsh 0.2.0-rc.2；真模型使用 DeepSeek-V41-Flash / high。以下不是国际化分支的新测试结果。

## 原因与修改

用户反馈的是提交后看到自己文字的延迟，和模型完成时间是不同指标。

- 前台分发本来就是同步的。成本来自整段对话替换、忙闲切换时重建已加载历史、滚动时立即读取布局，以及持久化回执重复触发。现在按容器保留消息 DOM，状态未变时跳过渲染，历史控件单独更新，布局读写合并到 DOM 更新之后。重来控件使用稳定容器，不在开始时改变气泡宽度；模型突发更新每帧合并一次。
- 后台提交原来先等 fork/resume/MCP 才显示。现在待提交和失败状态立即保留完整文本，提供重试和移除，成功任务归属创建时捕获的源对话。失败不再静默插入前台轮次；早到的任务事件等待任务进入渲染器。
- 新会话会重新连接 MCP。应用最多为当前目录/MCP 指纹准备一个未使用会话，每个话题消费独立会话，配置变化即丢弃。最多增加一个 agent scope 及其 MCP 连接，不跨会话共享有状态客户端。冷启动和 fork 恢复仍需初始化。
- 真正连接失败的 MCP 配置会跨会话暂时排除 30 秒；到期、配置变化或明确重载允许重试，失败状态保持可见。
- dsh 已有 `agent/assistant-stream`，但 ACP 只转发完成的回答块。带版本的 `viva-stream` 插件通过 Node IPC 投影实时正文/推理，工具、权限和用量仍走 ACP。没有修改依赖或 node_modules。
- 每次 prompt 前协商流式来源，结束时用传输屏障处理 ACP/IPC 任意到达顺序。块结束替换临时内容，重试移除失败尝试，持久事件确定最终文本。通道断开先回滚该通道临时输出，再重放完整 ACP 内容。操作 id 含桥接实例 UUID，避免 dsh 重启覆盖先前回答。
- 停止期限在等待取消前开始；计时器和迟到完成绑定操作对象，旧计时器不能停止同会话的新轮次。命令脱离不证明底层进程停止。

## 测量

使用实际 Electron 和真模型，驱动调用同一 DOM 点击/提交处理器；不是硬件鼠标到显示的延迟。窗口可见且聚焦，仅 QA 驱动禁用了后台节流。

| 输入字符 | 修改前普通点击 | 修改后普通点击 | 修改前后台文字入 DOM | 修改后后台文字入 DOM |
|---:|---:|---:|---:|---:|
| 100 | 34.4 ms | 0.9 ms | 1698 ms | 0.5 ms |
| 10000 | 46.9 ms | 2.5 ms | 1685 ms | 0.6 ms |
| 20000 | 55.6 ms | 4.2 ms | 1737 ms | 0.7 ms |

最终对比前台约 66–98k 字符；最终历史 216k，基线 29k，因此不是同一 DOM 快照。最终点击中同步 Layout 为零；基线分别为 28.8/38.2/45.8 ms。最终点击后首次文档 Paint 约在 6/10/22 ms，Paint 和两次 RAF 不能证明 compositor 已呈现。

后台/新话题使用故意延迟 1500 ms 的 MCP 初始化；后台就绪仍等待它。等待预热后，新话题三次为 264/59/59 ms，对比先前冷路径 1659–1707 ms；首次含长对话转入历史。未预热或快速连续切换仍可能冷初始化。

单独合成基准中，相同 1000 条消息/200k 字符重渲染，对话 2.7 ms、历史 1.6 ms，之前约 98/108 ms。这是热 DOM/布局检查，不是模型或点击到绘制测量；首次插入和真实宽度变化仍需布局。

真实前台回答与无关后台计算同时运行。后台文字 0.4 ms 可见，返回 `1674`，两项各结束一次且无错误。前台首推理增量 1.12 s、首正文 30.33 s、完成 38.08 s；最终 Markdown 与规范提交文本一致，只有一个助手气泡，旧历史节点保持挂载。

216k 历史字符下，120 次程序化宽度变化的 RAF p95 为 8.4 ms，空闲和真实流式中均无超过 50 ms 间隔。这是 `BrowserWindow.setBounds` 工作负载；原生连续拖边和用户另一台已安装 Windows 机器仍未验证。

## PR #46 后续

初次 CI 的 615 单测通过，但两平台长回答滚动检查失败（问题顶部 macOS 142 px、Windows 184 px）。布局、流式渲染和打字机更新改用一个 rAF 与 50 ms 后备竞争的调度器，取消输家并忽略迟到回调。禁用全部 rAF 的实际 Electron walkthrough 通过，问题顶部 24 px；确定性测试覆盖超时、取消、合并和先读后写。

单改后备调度未解决 CI。921×648 本地窗口正常帧下复现约 190 px。跟踪发现浏览器自动锚定在 DOM 更新与延迟跟随后改变偏移，滚动处理器误判为用户移动而过早停跟。现在自动跟随拥有滚动偏移时才禁原生锚定，到达上限或用户接管后恢复。相同小窗 walkthrough 为 24 px；常规冒烟固定覆盖短视口，0–80 px 门槛未放宽。

投机创建与明确请求分开：失败预热丢弃，不改当前 MCP 报告/冷却，不能留下静默缺失冲突服务器的备用会话。模拟 ACP 和实际 dsh 的独占端口 MCP 测试覆盖第二进程拒绝、下一真实会话成功；真实请求失败仍有 30 秒冷却。

失败提交按钮使用既有小型描边样式和明确 button 类型。架构文档记录内部流事件依赖、回退、升级测试和额外 MCP 资源；保留并解释同步取消错误保护。后续 Windows typecheck/build 与 **621 tests** 通过，跨平台 CI 在 PR #46 跟踪。
