# Viva file memory: ReMe behavioral reproduction

[简体中文](memory-reme-plan.zh-CN.md)

Two phases remain: R5a and R5b. The six-phase boundaries and order are unchanged. This plan replaces the old memory organization, processing and retrieval design. ## Files and ownership

Each authorized scope has a backend-selected root. Models use relative paths only:

```text
session/dialog/<session-id>.jsonl
daily/YYYY-MM-DD.md
daily/YYYY-MM-DD/<name>.md
digest/{personal,procedure,wiki}/<name>.md
metadata/
```

Markdown is authoritative for daily/digest. SQLite owns operations, receipts, dependency versions, exclusions and derived indexes, not a second memory truth. Backend metadata owns authors, source IDs and source versions. Frontmatter preserves name, description and extra fields; daily links session_id/source_conversation; entity tags use memory_tags. Daily uniqueness uses session/date. The owner assigns an opaque daily filename independent of its contents. Later model changes to name or description leave the assigned path and digest inbound links in place. An explicit rename must use a controlled transaction preserving logical identity, revisions and supersession while redirecting incoming links; old and new paths cannot become separate cards. The six tools do not include rename, and no explicit rename entry point is claimed.

Sources are explanatory sentences linking to full workspace-relative material paths. Digest relationships are contextual wikilinks. Do not append extensions implicitly; anchors and display labels are distinct from the target path. Read uses separate line arguments. Reject absolute/traversal/control-character/backslash paths and symlink traversal. One backend owns writes. Content hashes identify file snapshots, not global request-barrier revisions.

## Auto Memory

Consume completed turns, necessary preceding context, trusted IDs/authors/event times, a stable request ID and the existing daily card. Preserve speaker attribution; filter tool results and binary content. Assistant messages provide context, not user evidence. Record useful facts, preferences, decisions with reasons, progress and reusable experience. Update the day index. The backend assigns the opaque filename, resolves collisions and verifies ownership. Later updates retain that path while allowing title and body changes. Use message dates in the configured timezone; recovery time must not redate history.

Replay completed identical requests; reject a reused ID with different input. A true no-content skip differs from computation failure. Mark turns complete only after saving the card. Reject stale results if dependencies changed. Newly saved daily material is searchable immediately.

## Auto Dream

Extract refreshes day indexes and scans changed daily versions. Emit `{units:[{name,bucket,summary,paths}]}` across files, not one summary per file. Paths must belong to changed input. Buckets are personal/procedure/wiki; unknown strings fall back to wiki like the reference. Merge same-name units within a scope, union paths and keep the richer summary. Valid empty output is success; malformed output gets the reference bounded correction attempt, then failure. Split unprocessable multi-file requests. Never checkpoint failed, unseen or budget-deferred input.

Integrate runs once per unit with node_search, read, frontmatter_read, write, edit and frontmatter_update. Retrieve node summaries first, read likely candidates, distinguish same_abstraction/related/unrelated. Successful integration must choose CREATE/CORROBORATE/REFINE/CORRECT, write exactly one digest target, and do not SKIP. Preserve sources and links; explain supporting and related links in prose. CREATE uses the proposed bucket; updates may target an existing abstraction in another bucket.

All model edits affect an isolated draft. Verify the final target, receipt, sources, scope and expected versions before commit. Span checks establish provenance, not semantic correctness; semantic validation must cover negation, time, conditions and third-party attribution. Technical failures remain retryable; ambiguous evidence or missing user information enters the deferred state below without a forced commit. Return `{action,target_path,note}` and verify it against actual staged edits.

The four actions constrain successful commits only. Insufficient evidence is neither a fifth successful action nor SKIP. R3 persists deferred/pending_clarification with the unit, reason, node/canonical-source versions, readset and operation identity. Do not checkpoint or repeatedly retry it as a technical error. Deliver questions only when actual recall needs disputed information; never present it as established fact or force background questions. Validate answers against current authorization/source/node versions and resume work idempotently. New evidence or node changes trigger reevaluation and invalidate old questions; cancelled/stale answers cannot commit. R3 ships the state machine and basic query/answer APIs; R5a/R5b reuse existing host conversations for basic questions/answers, with the complete clarification management workflow deferred. This is an explicit reliability difference, not a property attributed to ReMe's four actions.

Before R3's first automatic digest rewrite, implement durable document revisions and a basic undo domain API. Each revision records before/after content, valid sources/versions, operation ID and receipt, published with the new body through one recoverable commit plan. Replays cannot create duplicate revisions. Completed commit intents are cleared and cannot substitute for history. Undo creates a new revision, checks current target/source versions and rejects overwriting newer changes or restoring forgotten evidence. Logically immutable history remains subject to explicit erasure; R3 must clean history copies on forgetting, while R5a adds a basic undo action and history browsing is deferred.


Finish checkpoints only processed input with no dependent failed unit, using the version originally read. Changes during processing remain pending. Auto Tag touches only actually changed files, once per file. Tag failure does not roll back successful integration or alter checkpoint decisions; no invented tag retry policy.

## Reference defaults

Defaults come from the pinned DSH integration, default.yaml, DreamExtractStep and SearchStep, not a universal ReMe setting: note interval 5 turns; integration timezone Asia/Shanghai and dream time 23:00; scan days 2; max units 5; dream batch budget 40,000 file bytes and per-file read limit 60,000 Unicode characters (oversized files form their own batch; truncated reads carry a marker); search limit 5, maximum 50; candidates min(200, limit × 5); vector weight .7; RRF k 60; min_score 0; chunk byte target 10,000; inbound/outbound neighbors at most 10 each. Verify behavior and units, not just numeric equality. Local embeddings are enabled by Viva choice; ReMe disables them by default.

## Retrieval and indexing

node_search retrieves digest node summaries for integration. search retrieves daily/digest chunks, fuses lexical and vector candidates, and uses single-arm ranking on fallback. Scores are not probabilities. AST chunking preserves frontmatter, ancestor headings, tables, code, lists, wikilinks and original line ranges. No arbitrary recent-file or prefix truncation.

Explicit corrections persist an old-content→effective-correction relation in document revision metadata, bound to logical document/source IDs, read versions, fragment ranges and applicability conditions/time. This is evidence metadata for document revisions, not another atomic-fact truth store or predicate-table/latest-write-wins rule. R3 commits it recoverably with CORRECT body/receipt; R4 indexes are derived views. Renames preserve logical identity; external edits that break fragment alignment quarantine affected content for revalidation instead of silently dropping supersession.

Default current retrieval, injection, node_search, read, relation expansion and profiles share applicability status. Explicitly superseded fragments cannot be given to the model alone as current facts. Evidence inspection or historical questions may return original text with superseded status, applicability time/conditions and correction references. Authorization, disablement and forgetting still take precedence; no history-browsing UI is added. Mark affected fragments of mixed notes, not unrelated content; uncertain alignment cannot be presented as current fact. If the correction becomes unavailable through disablement/forgetting/deletion, old fragments do not automatically become current: return unavailable/uncertain until new valid evidence or version/source-validated explicit undo establishes applicability. Status/correction references join the dynamic readset; caches, reindexing and late compute cannot bypass them.

Results carry path, lines, text, scores, neighbor summaries and counts. Distinguish no matches from results already delivered to the tool context; invalidate dedup on revision change. Startup scan and file changes update nodes, chunks, links, lexical and vector indexes; deletion removes all derived data. Like ReMe, reindex rebuilds from accepted chunk snapshots; filesystem rescan is separate. An embedding-space change disables old-space retrieval until rebuild completes.

## Changes, forgetting and recovery

In R5a, stopping daily content applies to the selected content version and its verified source ranges, not a permanent block on the session/date container. The logical identity and normal opaque path stay stable. When a previously accepted external name could expose stopped evidence, a safe rebuild retires that name and its aliases and publishes an opaque path. Restrictions and records needed for authorized management reading and explicit re-enabling remain durable; independent later input may produce a new projection through existing safe rebuilding, without carrying restricted old summaries or automatically removing restrictions. Management state must distinguish current content availability from still-active restrictions instead of conflating both in a boolean. Each restriction has a stable `restrictionId` independent of file identity, bound to the selected content version, canonical source versions and exact ranges. Re-enabling releases only that restriction, respects other restrictions, supersession and forgetting exclusions, and triggers safe rebuilding rather than promising restoration of an old summary. Keep one accepted snapshot per active daily restriction, available only through an explicit restriction selection. Source withdrawal erases that snapshot if any of its evidence is withdrawn, preserving an independently supported restriction and its remaining references. Management reads bypass only use-disable filtering, never authorization, secrets, forgetting or unverified external edits; management bodies must not flow back into model tools, injection or history. Daily gains no complete undo history for ordinary updates; it returns `undo: null` when no correction can be undone. Digest reuses its existing revision chain, binding undo to a specific changeId and expected content/usage/policy versions.

CORRECT is an evidenced document revision, not latest-write-wins. Ordinary history remains; explicit forgetting overrides the normal additive-link policy. Commit exclusion and global revision first, immediately block new reads/admission and stale result commits, then revoke/drain existing dispatch permits through the barrier protocol below before cleaning sources, daily, digest, history and indexes. Hide mixed-source documents and rebuild from remaining evidence. Distinguish evidence dependencies from merely related links; do not delete every connected document.

Use one operation vocabulary: the memory UI's Delete maps directly to forget, with no ambiguous third deletion state. Removing a host chat copy remains the occurrence operation described below, not memory deletion.

| Operation | Content and availability | Restoration and derived data |
| --- | --- | --- |
| setEnabled(false) | Retain body/revisions, persist a use restriction blocking model retrieval/injection/profiles and related derivation; authorized management UI may inspect | Explicitly reversible; bind restriction to logical target identity, supporting source fragments and derivation edges so dream rename/copy/reindex cannot bypass it; affect only selected content/dependencies, not unrelated history |
| setEnabled(true) | Check current version, authorization, available sources and absence of forgetting before lifting that restriction | Does not cancel other restrictions, supersession or exclusions; cannot revive forgotten content |
| forget / Delete memory | Persist exclusion, complete dispatch fence, erase target and related source/derived/history copies; pending cleanup remains queryable | Enable/undo cannot restore it; retain minimal body-free exclusion/receipt identities to prevent reingesting old sources/copies |
| undo ordinary revision | Create a new revision after version/source/eligibility checks | Does not implicitly enable content, undo forgetting or overwrite later revisions |

Disable/enable updates the use version and validates in-flight requests/results. Disable invalidates affected contexts/permits and follows the dispatch-fence completion protocol without erasing content. Equivalent copies derived from the same source fragments inherit restrictions; unverifiable lineage cannot be used to bypass them. Independent later user input follows normal admission, not a permanent text/concept blacklist. Automatic jobs cannot disguise old sources as new input via new files/IDs or silently enable the original item.

There is no cross-medium SQLite/filesystem transaction. Persist an operation intent with expected source/target versions and the new hash; sync a same-directory temporary file, atomically replace, then finalize the receipt. Recovery compares actual hashes: new → finalize; old → retry; other → conflict. Multi-file card/day-index updates need recoverable plans, and partially published plans stay invisible to models. Watchers ignore temporary files. Single-file rename alone is not a complete transaction.

## Independent core, host adapters and delivery

### Goal and current state

The entire memory system provides a reusable Node core. Viva, standalone DSH and `dsh web` share its domain rules; other Node hosts implement ports. Browsers consume server APIs and do not run the database or engine. Independent means no Viva, Electron or parent IPC requirement, not model processing without a model or storage.

At the pre-P1 `4069760` baseline, `plugins/memory/lib/adapter.ts` returned without `process.send` and imported repository shared files, while `compose.ts` owned mutation coordination, admission, task dependencies and withdrawal orchestration. P1 moved domain coordination into core; P2 now moves storage ownership, ingestion and model request barriers into the plugin, with Viva as a client. The installed artifact has passed a targeted real DSH Web flow without a parent process. The P2 implementation section records its coverage and outstanding acceptance; this does not establish delivery of the complete document memory system or Web management.

### Packages and dependency direction

Keep one repository and extract actual boundaries incrementally. No mandatory always-running HTTP service. Names below are logical; publishing names remain undecided.

| Module | Responsibilities | Dependency boundary |
| --- | --- | --- |
| `memory-contracts` | Normalized events, access contexts, operations/results/errors, versioned RPC and management snapshots | No Node, DSH or Electron; browser-safe |
| `memory-core` | Ingestion, daily/dream, evidence/dependencies, revisions/undo/clarification, retrieval policy, jobs/receipts/recovery, forgetting/admission state machines | Contracts and explicit ports only; no DSH/Viva/Electron, process.send or global fetch hook |
| `memory-node` | Default SQLite, files/journal, process lock, derived indexes, local embedding worker and resource disposal | Ordinary Node; configured model/worker paths, no Electron installation assumptions |
| `memory-dsh` | DSH events, model/tool protocol conversion, actual-send barriers, question delivery and authenticated Remote management | Contracts; uniformly composes core/node and exposes generic host clients; no reverse calls to a Viva-owned core |

| dsh-web adapter | Server authorization mapping and existing Web conversation integration; dedicated management views deferred | Same server core; browser uses contracts and authorized APIs only |

Keep pure document functions, domain services, job orchestration and queries separate inside core; do not merely move the large Runtime into a larger class. Storage ports represent transactions, snapshots and intents, not every fs function. Initially provide one Node storage implementation. Core publishes domain events; hosts translate them into UI notifications.

### Minimal ports and identity

- `ConversationFeed`: trusted host supplies owner/project/thread, event ID, message version/role/time, completion/edit/withdrawal and replay cursor. Core uses normalized values, not DSH Session/Agent objects. On reliable message receipt, durably register canonical source, occurrence, original role and version before advancing the receipt cursor. In-turn memory tools and model dispatch await registration. Separately mark completed turns before automatic note processing; receipt cursors and processing checkpoints recover independently. DSH session/event is an asynchronous notification after in-memory commit; session/flush is an awaited durability checkpoint; restored seeds do not re-emit events. Require flush cooperation, startup replay and receipts, not listeners alone. Internal note/dream work must not re-enter as user conversation.
- `SourceLineage` (required ConversationFeed fields): canonicalSourceId/sourceRevision identify original evidence; a host occurrence identifies its appearance in a conversation. Cold restoration preserves identity; fork prefixes add references, not new evidence; new branch messages have independent identities and nested forks retain root lineage. Compaction summaries, tool rewrites and agent-generated content are derived context with recursive source dependencies, even when DSH assigns role=user. Ordinary DSH forks may lack parentSession; P2 must verify and persist mappings, extending the host if necessary, rather than guessing from text hashes or new session+seq. Missing verifiable mappings block related ingestion/dispatch until restored. Deleting a branch copy removes its occurrence only; explicit root-source forgetting propagates to registered forks/summaries without deleting unrelated new branch messages. Mappings, withdrawal logs and ingestion cursors recover without assigning fresh identities to old copies and bypassing exclusions.
- `ModelCompute`: core declares tasks, input, controlled tools, cancellation and dependencies. Adapter translates messages, streams, tool calls, usage and completion. Provider reasoning/replay state stays adapter-local and job-isolated. Require explicit completion, never accept a truncated stream as success. Credentials/DSH configuration stay in adapters. A non-DSH implementation powers independent Node tests; first product adapter uses DSH, without implementing every provider up front.
- `Embedding`: query/passage text to vectors/unavailable plus space fingerprint. Adapter declares and validates dimension, normalization and model version; no domain constants for these. Reuse the validated local model configuration in ordinary Node with lexical fallback. Any future remote embedding adapter must also enforce send admission.
- `MemoryAccess` / `DispatchAuthority`: host authenticates the principal and binds owner/project/operation permissions; core validates availability, dependency versions, job generation and leases. Browser/model scope, session IDs, paths and job IDs are not authority. Source access, search and subscriptions share permission enforcement; access to one session does not imply access to all owner memory. Default to one trusted owner per installation; tabs/connections are not users. Multi-user support is deferred; no multi-owner runtime mode in this delivery.
- `HostEffects` / management API: hosts deliver questions, invalidate context, erase source copies and notify. Commands have stable IDs, recoverable receipts and status queries; core persists domain state. List/search/edit/disable/delete/basic undo/clarification/rescan/reindex use the same service. Revision records support undo/recovery without requiring a public history-browsing API. Queries return snapshot versions; writes check expected versions. Errors distinguish unauthorized, stale, unavailable and cleanup-pending without leaking paths/credentials.

Host-initiated history edits/deletions need a reliable reverse protocol, not asynchronous source events alone. Persist a mutation intent/outbox with stable operation ID, scope, operation semantics, occurrence/canonical source ID, expected version, replacement source and source sequence; core idempotently prepares invalidation within the operation scope, increments revision, completes the dispatch fence below and acknowledges. Only then commit the history edit/deletion, tombstone and outbox state in one host transaction, followed by source-ordered, idempotent core finalization and host cleanup acknowledgments. Replacement ingestion and operation receipts must also recover; query/replay the same operation after a lost reply without duplicating the replacement. If core is unavailable, leave the operation pending rather than deleting history before notification: core background jobs could otherwise still send old content. Host failure after prepare retains the barrier for recovery, never automatically undoes exclusion; do not report completion prematurely. Host database/transaction/outbox stays host-owned; core persists prepare/completion idempotency without sharing transaction objects. Startup/reconnect drains pending withdrawals and synchronizes watermarks before enabling affected contexts/tasks. Nontransactional sources need durable intents/deletion logs and equivalent ordering barriers; without these, do not claim atomic cross-system forgetting.

Source changes follow monotonic intent → preparing → prepared → host-committed → completed states. Host persists intent; core records preparing before durable invalidation and returns a prepared ticket only after exclusion/fence. Host commits its data with commit proof/outbox state; core validates and records host-committed, then completes when cleanup/receipts settle. getOperation reports the persisted phase, next step and responsible party; host-local completion not yet delivered is not core-confirmed. Prepare payload/target/expected version is fixed; duplicates replay current state and changed payloads conflict.

Cancelling a caller's wait never implies rollback. Cancellation may terminate an operation only when core atomically confirms it has not entered preparing or caused invalidation; unknown results require querying. After preparing, cancellation/timeouts/transient errors retain recoverable pending coordination, never undo exclusion or apply generic failed/cancelled terminal semantics. Host retains source-ordered intents, retries or reports conflicts, and blocks subsequent user mutations of the same target. commitSourceChange validates ticket, host, fixed target/version and legal phase. After reconnect, obtain the current ticket for the same operationId and finalize idempotently against host commit proof; late duplicate commits return the original state. Old connections cannot use old-epoch permits, while domain operations survive restart. Unrecoverable host conflicts retain the barrier with a visible reason, not fabricated completion or automatic restoration. This is the existing source-mutation protocol, not a generic distributed transaction framework.

Core-directed host cleanup is not a new user history mutation. HostEffects bind trusted causeOperationId/effectId/version/target/semantics; hosts use an internal cleanup path without another prepareSourceChange. Database cleanup and executed receipt persist in one host transaction. Nontransactional resources such as files use the host's existing durable intent/recovery and record completion only after actual cleanup. Returning source events carry causality, are checked against the core command/result and acknowledge the original operation idempotently, without recursive withdrawal/revision increments. Repeated effects or lost acknowledgments resend the same receipt. Genuine new user events still require prepare; browser/model input cannot forge causality to bypass authorization. Source ordering for pending user intents does not block authorized cleanup required to finish them.

Operation semantics must distinguish occurrence removal/edit from canonical withdrawal/correction; a shared source ID alone does not determine scope. Branch-copy deletion invalidates that occurrence, its host context and derived references depending on that occurrence, without a global canonical exclusion or affecting other authorized references/unrelated new branch messages. Branch editing defaults to detaching the old reference and creating independently identified branch evidence. Only explicitly authorized root correction/forgetting invalidates the canonical source and all dependencies. Prepare, recovery and cleanup receipts retain identical operation scope; a failed branch-local operation must not escalate to global deletion.

Safety ports must be explicitly supplied with validated capabilities; no default allow such as validateDispatch = () => {}. Core returns stable evidence references; hosts resolve source links and own UI copy/i18n.

Distinguish wire version, database schema, file hash, source version, global revision and job generation. RPC requires handshake, cancellation, timeout, idempotent operation IDs and outcome queries after reconnect. A timed-out write is not proof that nothing executed; do not retry under a fresh ID.

### Plugin-owned core and a single owner

- **Viva, standalone DSH and dsh-web use the same composition.** The DSH server plugin creates core/Node storage and owns the sole database/file writer, consolidation and indexing jobs. It ingests DSH conversations, injects retrieval context and registers memory tools. Viva no longer extracts/injects per turn, creates MemoryRuntime or opens memory storage. Windows, sessions and Web connections do not create separate engines.
- **Viva is a host client.** Existing UI calls Electron IPC, a thin backend adapter, then the plugin API over a trusted process channel. Host history transactions/outbox, business schedules, trusted project mapping, evidence navigation and copy cleanup remain host-owned. The plugin ingests ordinary DSH conversations; the host supplies aliases, permissions and host-only history/task events, never duplicate turns.
- **Other Node hosts can use the standalone library.** core/node accepts non-DSH model/source ports without DSH dependencies. The first product deployment supports plugin ownership only, without remote-core mode or another always-running memory service. The ordinary Node harness proves code independence rather than another product deployment.

When DSH is unavailable, memory is temporarily unavailable too. Viva opens no fallback database, fabricates no empty result and creates no second owner. UI shows unavailability. Writes require a durable acceptance receipt before being shown as pending; callers retain the same operation ID for retry if the plugin never accepted them. Host history mutation intents remain in its outbox; without core prepare, do not commit the history mutation or claim completion. No offline memory-management guarantee. If DSH can load storage without a configured model, expose supported model-free operations via capabilities, but P2 must verify this rather than assume it.

Each real data root has a process-level single-writer lock, including aliases/duplicate mounts; PID reuse or timeout cannot steal a live lock. Acquire ownership, establish owner epoch, restore exclusions/intents/jobs and bound-host withdrawal watermarks before enabling affected requests and reporting ready. Plugin restarts reuse the same root, never create a database per model/session/project. Trusted startup configuration selects the root, never browser/model input.

Disposal stops ingestion/new jobs, closes admission, cancels/drains compute, persists work, then closes storage/releases the lock. Clients handshake and query unknown outcomes after restart. Old leases/receipts do not authorize new work; reload cannot duplicate subscriptions, schedules or hooks. Normal forgetting completes its barrier inside the plugin, replacing the old pattern of stopping DSH and then calling its now-absent core. After abnormal termination the new instance restores exclusions/pending operations before sending; confirmed old-process exit settles sender uncertainty. DSH restart availability applies equally to Viva and Web.

### Request barriers and forgetting protocol

Core decides eligibility; adapters enforce it at physical dispatch. Leases bind trusted caller, owner epoch, job generation, global revision, dynamic readset and deadline. Foreground/background/scheduled/recovered tasks, note/dream stages, semantic checks, next tool-loop steps and every SDK HTTP retry/redirect replay require admission. node_search summaries, read bodies, tool results and retained reasoning contexts carry dependencies. New reads update deadlines; later dispatch and final commit revalidate them.

First persist exclusion and increment revision to reject new reads/admission and stale result commits, then complete the dispatch fence and clean core/host copies. Already-sent requests cannot be recalled, but their late results cannot commit; provider retention is outside local erasure. Durable host commands clean history, background/schedule payloads and recovery context. Failure remains “use blocked, cleanup pending,” never fully erased. Restart/retry/undo/late receipts cannot resurrect excluded material. Hosts without verifiable cleanup cannot claim end-to-end forgetting.

Admission and mutation share a serialized coordination protocol. A permit is a tracked in-flight lease held until transport explicitly commits the request body or confirms abandonment, not permission to send arbitrarily later outside coordination. Adapters must specify an observable transport commit boundary; multipart/streamed bodies remain in flight until finished. After closing new admission, forgetting revokes unsent permits and waits for confirmed transport stop or existing sends to drain. Requests actually sent concurrently with revocation are recorded as irretrievable. Only crossing this fence establishes that old content will no longer leave this system; persistent exclusion alone does not complete it. Cancellation return, disconnect or lease timeout alone cannot prove the remote sender stopped. Unconfirmed disconnected leases remain pending and block affected recovery work. Verify that the old transport has stopped, terminating its host execution process when necessary; a new owner cannot dismiss an old sender merely by changing epoch. Core persists recoverable revocation/fence state; adapters cannot reuse old permits before reconnect.

Checking only at stream start is insufficient. If global fetch/undici hooks remain necessary, encapsulate them in the DSH adapter and verify coexistence, disposal and reference counting; no core global side effects. An adapter lacking per-physical-send guarantees must reject memory-dependent computation instead of silently weakening the barrier. This applies to future non-DSH adapters too; cancellation alone is not a dispatch barrier.

### Generic host API and Viva integration details

Separate the public memory service, trusted host collaboration and core compute ports. Public APIs expose neither ModelCompute nor raw storage, root paths or send permits; model tools receive only their authorized subset. Host clients depend solely on memory-contracts. Electron IpcEvent, ACP objects, Viva conversation/task structures and DSH Agent/Context must not cross contracts. Names below describe logical interfaces, not a requirement for separate packages or a new service framework.

| Group | Generic operations | Contract and boundary |
| --- | --- | --- |
| Connection/capabilities | connect, status | Protocol version, instanceEpoch, ready/recovering/unavailable and supported operations/compute capabilities; connection adapter binds authenticated authority, never client-asserted owner; reject incompatible versions |
| Queries | list, search, read, getProfile | Bound authorization context; opaque memory IDs, versions, content/hit lines, source references and partial/unavailable reasons; no host paths, DB objects or credentials |
| Writes/management | remember, revise, setEnabled, forget, undo, setProfile | operationId and expectedRevision for mutations; distinguish explicit user input from evidence-checked model proposals; core validates forget target/scope rather than accepting arbitrary source IDs |
| Consolidation/maintenance | runDream, rescan, reindex | Authorized host controls return queryable operations; ordinary model tools do not become administrative commands; scheduled wakeups remain plugin-owned |
| Operations/minimal interaction | getOperation, answerClarification | Durable acceptance, running/cleanup-pending, complete or failed; authorized outcome queries and version-checked answers; undo uses returned revision/change refs without a history-list page |
| Source binding/transfer (trusted) | bindContext, linkSources, attachDependencies | Map namespaced host thread/project/message/task references to canonical sources and DSH sessions; authenticated host adapter only, with verified event mapping; derived summaries/tasks carry core-issued dependency references revalidated on reuse, not client assertions of validity |

| Host-copy cleanup (trusted) | pendingHostEffects, ackHostEffect | Durable causeOperationId/effectId/version/bound host/minimal source refs; host performs idempotent local cleanup and acknowledges the version; pull recovery on disconnect rather than reliable delivery via UI notices; hosts without their own copies need no fabricated cleanup handler |

**Recovery and capability negotiation.** connect/status/getOperation and trusted source-mutation/cleanup acknowledgments required for recovery remain callable while recovering, avoiding a ready-before-cleanup/cleanup-before-ready deadlock. Affected retrieval, compute and new business writes stay closed. Startup configuration binds required hosts/capabilities; only the bound host can certify its synchronization watermark. Arbitrary connections cannot impersonate it, stall recovery or acknowledge cleanup. Pure DSH conversations need no Viva history-copy capability. Paths with host-owned history/task copies must supply matching cleanup/dependency-transfer capabilities or be explicitly rejected, never silently weaken forgetting guarantees.

**Command semantics.** requestId correlates one transport call; operationId identifies a domain write. Within the authenticated client/operation namespace, identical ID/input replays the original result and changed input conflicts. Identity namespaces survive restart; instanceEpoch invalidates connections/leases, not durable write idempotency. Use serializable DTOs, TypeScript discriminated unions and runtime schemas. Translate local AbortSignal into transport cancellation instead of serializing it.

Query cancellation ends waiting. Write timeout/cancellation is not rollback: ordinary accepted work completes or records a durable terminal outcome. Source changes at or after preparing retain recoverable coordination under the source-mutation protocol, outside generic cancellation/failure terminal rules. Query by the original operationId before retrying, never silently generate a new ID. Distinguish accepted from completed; forgetting separately reports send-fence/copy-cleanup progress, never treats queue admission as erasure. Errors include unauthorized, invalid-input, revision-conflict, unavailable, protocol-mismatch and operation-id-conflict with structured parameters localized by the host. Ordinary asynchronous failure has a queryable terminal result; source changes report the current coordination phase and recovery reason; retries follow operation state without implicitly starting a fresh mutation.

**Minimal notifications and evidence navigation.** Viva may receive authorized memoryChanged/operationChanged invalidation notices containing only version/operation refs. Notices may coalesce or be lost; reconnect/page reopening refreshes snapshots. They never carry the reliable cleanup protocol or introduce a Web management subscription platform. Stable source references such as namespace/sourceId/occurrenceId are resolved by the host; core neither constructs Viva URLs nor opens files. Without host navigation, show authorized evidence excerpts rather than fabricated links.

**One ingestion/injection path.** DSH adapter registers sources when genuine user messages are reliably received, queues automatic notes only after turn completion, independently replays source receipt/processing progress and injects eligible memory. Ordinary Viva sends attach trusted context/message aliases, no longer calling accept/recordNoteTurn or composing memory prompts. Host messages mapped to DSH events retain one canonical source; explicit remember references that source and deduplicates by operationId. Host-only manual memory/profile inputs use public commands. Restored history, background handoffs and scheduled jobs use trusted mappings and inherited dependencies rather than new user evidence. Internal note/dream sessions never re-enter ingestion.

In-turn tools require registered original user content from trusted DSH receipt records/pre-step originals, never model tool arguments used to fabricate provenance. Asynchronous DSH event delivery alone cannot establish ordering: the adapter must await registration, rejecting dependent requests if it cannot verify it. Cancelled/failed turns are not completed and do not automatically create notes. Explicit remember/forget already committed is not rolled back by turn cancellation; query its original operationId. Retain verifiable user sources supporting committed operations; incomplete assistant output never becomes evidence. Event recovery preserves source and tool-operation identities without duplicate writes.

**Viva migration locations.** compose wires connection, project/source mapping and existing host outbox. memory-ipc converts existing UI actions to generic client calls, keeping source navigation/i18n. memory-withdrawal retains history transactions but calls prepare/commit. Plugin creates memory store/runtime/dispatch/embedder and memory jobs. memory-channel becomes neutral client transport/server dispatch, removing reverse requests to Viva compute/admission; internal model execution needs no host RPC. DSH downtime produces unavailable UI and pending host outbox recovery, never direct memory-file writes.
