# Viva 文件记忆：ReMe 行为复刻方案

[English](memory-reme-plan.md)

状态：2026-11-16，R1、R2、P1、P2、R3 已完成；R3 文档 dream、修订和恢复已通过本轮验收。剩余 R4、R5a、R5b 三个阶段；六阶段划分和顺序不变。本文替代旧方案的记忆组织、加工和检索设计；原文校验、权限、遗忘和请求屏障要求继续有效。旧数据不迁移。仅实现自研版本，不接入 ReMe 服务，不修改 ReMe 对照分支。

## 1 基准与范围

唯一行为基准为 agentscope-ai/ReMe 提交 `b13034ba2ff7339bb03df4fa4ee130b47a731c6c`。升级基准必须重新记录差异。这里的“复刻”指文本会话的 Auto Memory、Auto Dream、Markdown 文件体系和搜索行为，不包含整个项目。

- **照 ReMe 做**：session → daily → digest；frontmatter、Sources、wikilink；Extract → Integrate → Finish → Auto Tag；节点搜索与片段搜索分离；Markdown AST 分块、BM25/向量 RRF、链接展开。
- **Viva 必需差异**：后端绑定权限与来源，模型文件操作经过受控适配器；有效来源和版本检查；遗忘屏障；本地向量模型；任务恢复元数据使用 SQLite。
- **暂不做**：图像、外部资源摄取、主动发现、独立原子事实库、Hindsight observations/mental models、多跳推理 agent、额外重排模型。

ReMe 已知边界也要记录：任意 Agent 文件操作不是事务；回执提交前中断可能重执行；失败输入后续扫描窗口必须包含其日期才能重试；自动标签失败不会因没有文件变化而自行重试。Viva 的持久化待办恢复属于明确的运行可靠性差异，不声称来自 ReMe。

### 本轮范围确认（2026-11-15）

保留 session/daily/digest、完整 dream 四阶段（含 Auto Tag）、全文/本地向量检索、关系展开、索引重建、自动替换、画像、基础撤销与按需澄清，以及独立核心/DSH 插件、来源治理、遗忘和恢复保障。

仅后置以下四项，不计入 P1–R5b 的完成条件：

- Web 管理：专门的记忆管理页面及其管理状态订阅；真实 dsh web 会话中的写入、检索、遗忘接入仍需验收。
- 历史浏览：时间线、版本列表与差异浏览界面；内部修订记录、基础撤销 API 和可用撤销入口保留。
- 完整澄清工作流：独立问题中心、集中待办及跨页面处理界面；保留疑点状态、实际使用时通过宿主现有对话提问、答复版本校验与恢复。
- 多用户：多 owner 租户管理和跨用户共享等产品能力；本轮限定单 owner，保留认证、项目/会话授权和来源隔离，拒绝未授权访问。

后置不代表本轮删除既有界面，也不要求把旧界面完整迁移成新核心的发布前置。核心能力在 Viva/独立 DSH 中共用；Web 无须复制 Viva 的全套界面。以下“全项/对等/完整验收”均限于本轮保留范围。

## 2 文件与真值

每个授权范围使用独立、由后端选择的工作区根目录，模型只能看相对路径，不能选择其他 scope 根目录。

```text
session/dialog/<session-id>.jsonl
daily/YYYY-MM-DD.md
daily/YYYY-MM-DD/<name>.md
digest/personal/<name>.md
digest/procedure/<name>.md
digest/wiki/<name>.md
metadata/                  # 回执、目录版本、索引等，可恢复数据
```

Markdown 是 daily/digest 正文的权威来源；不把 digest 再拆成另一套正式事实。SQLite 管理任务、提交意图、回执、排除标识及派生索引，不维护独立记忆真值。原始作者、来源 ID、消息版本属于后端可信元数据，模型不能自行修改。

frontmatter 至少支持 name、description，并保留附加字段。daily 关联 session_id、source_conversation；标签字段为 memory_tags。可读文件名不充当会话身份；会话每日唯一性由 session ID + 日期确定。从 R3 起，daily 路径在首次分配后保持稳定；后续模型修改 name、description 或建议 filename 不触发隐式路径重命名，也不直接改写 digest 的入链。显式重命名只能通过保留逻辑身份、修订及替代状态的受控事务更新入链，不允许新旧路径同时被当作两张卡片；当前六工具不提供 rename，不宣称已经交付显式重命名入口。

Sources 使用完整句子说明 `[[daily/...md]]` 支持什么。digest 之间的 wikilink 融入正文。链接目标是完整 workspace-relative 路径，可有显示名和 anchor；路径不隐式补 `.md`。读工具的行号参数与路径分开。

Viva 路径边界：拒绝绝对路径、反斜杠、`.`/`..`、控制字符及符号链接穿越。正式写入只能由单个后端所有者完成。文件内容 hash 是本模块快照版本；请求屏障仍使用全局内容 revision，两者不能混用。

## 3 Auto Memory

输入：已完成回合、必要前文、消息 ID/作者/发生时间、稳定请求 ID、现有当日卡片。只处理有实际新增内容的回合。保留用户/助手区分，过滤 tool-result 和二进制负载，助手内容只能作为讨论上下文，不能伪装用户依据。

按会话与日期寻找卡片，生成或更新有复用价值的偏好、事实、决定及原因、进度、经验。不生成流水账。更新日索引，使同一天的卡片可浏览。首次创建时模型可建议文件名；后端解决碰撞并验证归属。后续更新复用已经分配的路径，标题和正文可正常变化。

每日日期按消息时间及配置时区确定，不把恢复时间当作历史发生时间。请求 ID 相同且输入相同重放回执；相同 ID 不同输入拒绝。无值得写入内容是成功的 skip；模型失败不是 skip。

笔记保存成功后才标记该批回合完成。更新中的源版本改变时，旧结果不提交。笔记生成后可立即搜索，不等待 dream。

## 4 Auto Dream

### Extract

刷新扫描窗口中的日索引，读取相对 checkpoint 有变化的 daily Markdown。一次跨文件提取可复用抽象，不逐文件摘要。

输出契约为 `{units:[{name,bucket,summary,paths}]}`。paths 只能引用本次输入的 changed paths；bucket 为 personal/procedure/wiki，未知字符串按 ReMe 回退 wiki。同名 unit 跨批次合并来源，保留较丰富 summary。名称合并仅限当前授权范围。

正确空数组表示无可复用内容；格式失败先按上游规则纠正一次，再记录失败；请求无法承载多文件时拆批隔离。失败、未扫描和因 unit 预算延后的文件不得 checkpoint。预算与截断规则按基准实现，不擅自增加最近 N 张或返回正文开头的限制。

### Integrate

每个 unit 一个计算会话，工具限定为 node_search、read、frontmatter_read、write、edit、frontmatter_update。先查询 digest 节点摘要，再读取相关正文。分类 same_abstraction / related / unrelated。

成功整合必须选择 CREATE / CORROBORATE / REFINE / CORRECT，并且只写一个目标 digest 节点。CREATE 落到对应 bucket；更新可跨 bucket 命中已有抽象。没有 SKIP。保留已有来源和链接，补齐 unit 依据，把相关节点链接写入有上下文的句子。

模型操作先作用于隔离草稿；读取最终草稿、验证一个目标、有效来源、允许范围、预期版本后才能正式提交。原文跨度检查只能证明出处，不能证明概括正确；语义核验必须覆盖否定、时间、条件及第三方归属。不能把“需要语义核验”伪装成确定性字符串校验。技术性失败保留可重试待办；证据含糊或缺少用户信息进入下述 deferred 状态，不强行提交。

返回 `{action,target_path,note}`。后端核对回执与实际草稿写入一致。失败 unit 及来源路径留作失败；不能把“模型返回成功”当作已经落盘。

四动作只约束成功提交；证据不足不增加第五种成功动作，也不等于 SKIP。R3 必须持久化 `deferred/pending_clarification`：保存 unit、问题原因、涉及节点与 canonical source 的版本、读集及操作身份。该状态不 checkpoint，不进入技术失败的自动重试循环；仅在实际召回需要争议信息时投递问题，不把争议当确定事实，也不在后台强制提问。答案经当前权限/来源/节点版本校验后幂等恢复工作；新依据或节点变化触发重新评估，旧问题失效，取消/过期答复不能提交。R3 实现状态机和基础查询/答复 API，R5a/R5b 复用各宿主现有对话完成基础提问/答复，完整澄清管理工作流后置。这是明确的可靠性差异，不声称来自 ReMe 四动作本身。

R3 第一次自动改写 digest 前就必须具备持久文档修订记录与基础 undo 领域 API。每个 revision 记录变更前后内容、有效来源/版本、操作 ID 与回执，和新正文通过同一可恢复提交计划落盘；重复请求不能生成重复 revision。提交意图在完成后清理，不能替代历史。撤销创建新修订，校验当前目标及来源版本，拒绝覆盖后续修改或恢复已遗忘依据。逻辑不可变历史仍受显式遗忘的内容擦除约束；R3 同时覆盖历史副本清理，R5a 接基础撤销入口，历史浏览界面后置。


### Finish 与 Auto Tag

只有已处理且没有失败 unit 依赖的来源才能 checkpoint，保存的是本次读取版本而非完成时版本。处理期间发生修改仍留作新工作。按 ReMe 更新本轮扫描的日索引记录。

只对实际新增/修改文件打实体标签，同文件去重。打标失败不回滚已成功的整合，并单独记录；首次实现不额外发明自动标签重试策略。标签更新也经过文件版本校验。

## 6 搜索与索引

node_search 只查询 digest 节点的名称、描述等信号，供去重及关联发现，不自动展开正文。search 面向 daily/digest 的 FileChunk，全文和向量各自产生候选，按 ReMe RRF 融合；单路可用直接返回该路排名。分数不是概率。

明确更正须在文档修订元数据中记录“旧内容 → 有效更正”的替代关系，绑定逻辑文档/来源 ID、实际读取的版本与片段范围、适用条件和时间。它是正文修订的依据元数据，不新增原子事实真值库，也不按谓词表或最近写入时间推断替代。R3 与 CORRECT 正文/回执一起可恢复提交，R4 索引只是其派生视图。重命名保持逻辑身份；外部修改导致片段无法对应时先隔离受影响内容并重验，不能静默丢弃替代关系。

默认当前检索、自动注入、node_search、read、关系展开和画像共用替代状态：已明确被替代的片段不能脱离更正内容，单独作为现状交给模型。需要返回原文依据或回答历史问题时，可返回带 `superseded`、适用时间/条件和更正引用的原文；权限、停用、遗忘仍优先，不新增历史浏览界面。混合笔记只标记相应片段，不删除无关内容；无法可靠拆分时暂不把受影响结果当当前事实。更正内容因停用、遗忘或删除不可用时，旧片段不能自动恢复为当前事实，返回不可用/有疑点；只有新的有效依据或通过版本/来源校验的显式撤销，才能重新决定适用状态。状态与更正引用进入动态读集，缓存、重建索引和迟到计算不能绕过。

Markdown AST 解析 frontmatter、标题树、列表、表格、代码块和 wikilink；chunk 保留祖先标题与实际原文行号。先按结构分块，再按预算处理过长叶节点。不能退化为只取开头字符或固定最近文件集合。

结果提供 path、start_line、end_line、正文、得分、入链/出链邻居摘要及计数。需要更多内容时 read 使用独立行号参数。空命中与同一工具上下文已返回完毕区分。去重缓存随文件版本变化失效。

启动扫描和运行时文件变更更新 FileNode/Chunk/Link、BM25 及向量。删除移除全部派生数据。按 ReMe，reindex 从已接受的 chunk 快照重建派生索引，不等同重新扫描文件；全量扫描是独立修复操作。向量空间切换后禁用旧空间查询，重建成功后恢复。

## 7 更正、遗忘与恢复（Viva 必需差异）

CORRECT 是带来源的文档修订，不自动推断“最近写入的永远正确”。普通历史保留，遗忘删除不受“只增不删来源链接”的普通整合规则限制。

操作语义统一如下；界面“删除记忆”直接映射 forget，不另设含糊的删除状态。删除宿主聊天副本仍是 8.4 的 occurrence 操作，不能与删除记忆混用。

| 操作 | 内容与可用性 | 恢复和派生约束 |
| --- | --- | --- |
| `setEnabled(false)` 停用 | 保留正文与修订，以持久使用限制阻止模型检索、注入、画像及相关派生使用；授权管理界面可查看 | 可显式启用；限制绑定目标逻辑身份及支持该内容的来源片段/派生关系，dream 改名、复制、重建索引不能绕过。只影响选中内容与依赖，不封锁整段无关历史 |
| `setEnabled(true)` 启用 | 校验当前版本、权限、来源仍可用和未被遗忘后解除对应使用限制 | 不取消其它停用限制、替代状态或排除；不能复活已遗忘内容 |
| `forget` / 删除记忆 | 持久排除、完成发送屏障，擦除目标及相关来源/派生/历史副本；清理未完成保持可查询 | 不可通过启用或 undo 恢复。保留无正文的最小排除/回执标识，阻止旧来源及其复制品被重新摄取 |
| `undo` 撤销普通修订 | 通过版本、来源与有效性校验创建新修订 | 不自动解除停用，不撤销遗忘，也不覆盖之后的修订 |

停用/启用也更新使用版本并校验在途请求/结果；停用需使受影响上下文和发送许可失效，完成状态遵循 8.6 屏障，但不擦除正文。同来源片段派生出的等价副本继承限制；来源范围无法验证时不提交绕过限制的重建。之后独立的新用户输入按正常准入处理，不建立按文本或概念永久封禁的规则；自动任务不能借新文件或新 ID 把旧来源伪装成新输入，也不能自动启用原条目。

遗忘先提交排除标识和 revision，立即阻止新读取、新请求准入及旧计算结果提交；按 8.6 排空或撤销已有发送许可并确认屏障生效，再清理原始来源副本、daily、digest、历史和索引。混合依赖文档先失效，再由仍有效依据重建；不能把整篇笔记作为一个不可分的独立新证据复活被删内容。来源反向依赖包含内容依赖与普通关联链接，不能沿所有相关链接误删无关文档。

文件与 SQLite 无跨介质事务。正式提交采用持久化意图：记录 operation ID、源/目标预期版本、目标新 hash；写同目录临时文件并同步，原子替换后完成回执。恢复时比较实际 hash：新 hash 完成回执、旧 hash 重试、第三种 hash 标记冲突，不能盲目覆盖。多文件（例如日索引与卡片）使用可恢复计划，未完成计划不向模型暴露混合版本。临时文件不进入 watcher。

完成前崩溃测试必须覆盖意图写入、文件替换、回执与 checkpoint 各边界。单文件原子 rename 不是完整事务保证。

## 8 独立核心、宿主适配与交付

### 8.1 目标与现状

整个记忆系统提供可独立使用的 Node 核心，DSH 插件是完整接入方式之一。Viva、独立 DSH、`dsh web` 使用同一套领域规则；其它 Node 宿主只需实现端口。浏览器消费服务端 API，不运行数据库或核心。独立指不需要 Viva/Electron/父进程 IPC，不承诺无模型、无存储也能完成模型加工。

在 P1 之前的 `4069760` 基线，`plugins/memory/lib/adapter.ts` 在没有 `process.send` 时直接返回，且引用仓库内部 shared 文件；`compose.ts` 仍持有变更互斥、请求准入、任务依赖和遗忘协调。P1 已将领域协调迁到 core；本轮 P2 再将存储所有权、摄取与模型请求屏障迁到插件，Viva 通过客户端调用。安装产物已在无父进程的真实 DSH Web 跑通定向链路，覆盖范围和未完成验收见第 13 节；不能据此宣称整个文档记忆系统或 Web 管理已交付。

### 8.2 包与依赖方向

建议保留一个仓库，按实际边界逐批提取，暂不增加常驻 HTTP 服务。包名为逻辑名，正式发布命名另定。

| 模块 | 所有职责 | 依赖边界 |
| --- | --- | --- |
| `memory-contracts` | 标准化事件、权限上下文、操作/结果/错误、版本化 RPC、管理快照 | 无 Node、DSH、Electron；可供浏览器使用 |
| `memory-core` | 摄取、daily/dream、证据与依赖、修订/撤销/澄清、检索策略、任务/回执/恢复、遗忘与准入状态机 | 只依赖 contracts 和明确端口，不导入 DSH/Viva/Electron，不使用 `process.send` 或全局 fetch hook |
| `memory-node` | 默认 SQLite、文件/日志、进程锁、派生索引与本地向量 worker、资源关闭 | 普通 Node 可运行；模型文件和 worker 路径由配置提供，不能依赖 Electron 安装目录 |
| `memory-dsh` | DSH 事件转换、模型/工具协议转换、每次真实发送的屏障、问题投递、经鉴权的 Remote 管理入口 | 依赖 contracts，统一装配 core/node；对宿主公开通用客户端接口，不提供反向调用 Viva 核心的模式 |
| Viva 宿主适配 | UI/IPC 转发、可信身份/来源映射、任务依赖转交、宿主副本清理、进程生命周期 | 调用统一记忆 API，不能另做纠错、遗忘或恢复规则 |
| dsh-web 适配 | 服务端权限映射与现有 Web 会话接入；专用管理视图后置 | 复用同一服务端核心；浏览器只能使用契约和授权 API |

core 内仍分纯文档函数、领域服务、任务编排和查询服务，不能把现有大 Runtime 原样搬成一个更大的类。存储端口表达事务、快照和提交意图，不为每个 fs 函数创建接口；默认只有一套 Node 存储实现。领域事件由核心发布，宿主负责翻译为 UI 通知。

### 8.4 最小端口与身份

- `ConversationFeed`：可信宿主提供 owner/project/thread、事件 ID、消息版本/角色/时间、完成/修订/撤回及补读游标。核心接收标准化值而非 DSH Session/Agent。消息可靠接收时先持久登记 canonical source、occurrence、原文角色与版本，再推进接收游标；本轮记忆工具及模型发送须等待该登记成功。回合完成后另行标记 completed，才触发自动笔记加工；接收游标和加工 checkpoint 分开，崩溃可分别重放。DSH `session/event` 是内存提交后的异步通知，`session/flush` 是等待持久化的检查点，恢复 seed 不重发 event；必须实现 flush 协作、启动补读与幂等回执，不能只挂事件监听。内部 note/dream 计算不回流为用户会话。
- `SourceLineage`（ConversationFeed 的必要字段）：canonicalSourceId/sourceRevision 表示原始证据，host occurrence 表示它在某会话中的一次出现。相同会话冷恢复沿用身份；fork 继承前缀只新增引用，不生成新证据，分支新增消息有独立身份；嵌套 fork 同样追溯根来源。压缩摘要、工具重写与代理生成内容是派生上下文，递归继承来源依赖，即使 DSH 消息角色为 user 也不能变成用户原话。DSH 普通 fork 未必保留 parentSession，P2 必须验证并持久化源映射，必要时补宿主扩展，不能靠正文 hash 或新 session+seq 猜身份。缺少可验证映射时拒绝相关记忆摄取/发送，先恢复映射。删分支副本只清理对应出现记录；显式遗忘根来源传播到所有已登记分叉和摘要，保留无关分支新消息。身份映射、撤回日志和摄取游标必须可恢复，不能重启后给旧副本分配新身份绕过排除。
- `ModelCompute`：核心声明任务、输入、受控工具、取消和依赖；适配器翻译消息、流、工具调用、用量和完成状态。完整推理回放等 provider 状态留在适配器，以作业隔离；没有明确结束信号不能把截断流当成功。凭据及 DSH 模型配置留在适配器。独立 Node 测试使用非 DSH 实现；首版产品默认用 DSH 模型适配，不预先实现所有供应商。
- `Embedding`：输入 query/passage 与文本，输出向量/不可用、空间指纹；维度、归一化和模型版本由适配器声明并校验，不写进领域常量。本地小模型沿用已有验证配置，普通 Node 运行；不可用时全文回退。远端 embedding 若以后提供，也须执行发送屏障。
- `MemoryAccess` / `DispatchAuthority`：可信宿主认证 principal 后绑定 owner/project 与操作权限，核心再做来源可用性、依赖版本、任务 generation 和租约校验。浏览器/模型传来的 scope、session ID、路径或 job ID 都不是授权。来源读写、搜索结果及事件订阅使用同一权限；可访问一个会话不自动获得用户所有记忆。默认一个安装实例一个可信 owner，不把浏览器标签页/连接 ID 当用户；多用户后置，本轮不提供多 owner 运行模式。
- `HostEffects` / 管理 API：问题投递、上下文失效、来源副本清理和通知由宿主执行；命令有稳定 ID、可恢复回执和状态查询，领域状态仍由核心持久化。列表、搜索、修改、停用、删除、基础撤销、澄清答复、扫描/重建均走统一服务；修订记录供撤销/恢复使用，不要求公开历史浏览 API，查询返回快照版本，写入校验预期版本。错误码区分无权限、陈旧版本、不可用及待清理，不向外泄漏路径/凭据。

宿主发起的原历史编辑/删除必须有反向可靠协议，不能仅等待异步来源事件：先持久化稳定 operation ID 的 mutation intent/outbox（保存 scope、操作语义、occurrence/canonical source ID、预期版本、替换来源及来源序号），核心幂等 prepare 按操作范围失效、提升 revision 并完成 8.6 发送屏障后回执；收到回执后宿主在同一历史事务写入修订/删除、tombstone 和 outbox 状态，再按来源顺序幂等驱动核心收尾及宿主清理回执。替换来源接受与操作回执也需可恢复；核心已提交但回执丢失时查询/重放同一操作，不重复摄取替换来源。核心不可用时操作保持待执行，不能先完成历史删除再等待通知；否则核心自身的后台任务仍可能外发旧内容。prepare 后宿主失败保留封锁并恢复，不自动撤销排除；未完成前不对用户报告完成。宿主数据库/事务/outbox 留宿主，核心持有 prepare/完成的幂等状态，两者不共用事务对象。启动或重连先处理待撤回和同步水位，再开放相关上下文与任务；不支持事务的来源须提供持久意图/删除日志和等价顺序屏障，不具备该能力时不能声称原子跨系统遗忘。

来源变更使用单调状态 `intent → preparing → prepared → host-committed → completed`：intent 由宿主持久化；core 在开始持久失效前登记 preparing，排除及发送 fence 完成才返回 prepared 票据；宿主事务连同提交证明/outbox 状态一起落盘，core 验证并记录 host-committed，清理及回执收齐后 completed。getOperation 返回已持久阶段、待执行步骤及责任方，不能把宿主本地已提交但未送达的状态误报为 core 已确认。一次 prepare 的 payload/目标/预期版本固定，重复操作重放当前状态，异文拒绝。

取消调用者等待始终不代表回滚。只有在 core 原子确认尚未进入 preparing、未产生失效副作用时，操作才可结束为取消；结果未知时必须查询。进入 preparing 后，取消、超时或暂时错误只保留可恢复 pending，不撤销排除、不用通用 failed/cancelled 终态结束协调。宿主按来源顺序持久保留意图，失败重试或报告需处理的冲突，不放行相同目标的后续用户变更。commitSourceChange 校验票据、宿主身份、固定目标/版本及合法阶段；重连后以同一 operationId 获取当前有效票据，确认宿主提交证明后幂等收尾，迟到重复 commit 只返回原状态。旧连接不得直接使用旧 epoch 许可；领域操作跨重启延续。发生不可自动恢复的宿主冲突时保持封锁并暴露原因，不能伪造完成或自行恢复旧内容。这只是当前来源变更协议，不扩展为通用分布式事务框架。

核心发起的宿主副本清理不是新的用户历史变更。HostEffects 携带可信绑定的 causeOperationId、effectId、版本、目标和语义，宿主走专用内部清理路径，不再次调用 prepareSourceChange。宿主在同一事务中清理其数据库副本并持久化已执行回执；如涉及文件等非事务资源，用宿主既有持久意图恢复，确认实际清理完成后才记回执。回流来源事件携带该因果标识，经核心核对命令及结果后幂等确认原操作，不递归生成撤回或重复提升 revision。重投 effect 或丢失 ack 时重发同一回执；真正的新用户事件仍走 prepare，浏览器/模型不得伪造因果标识绕过授权。待处理用户意图对目标的串行限制不阻止完成它所需的已授权清理任务。

上述操作语义必须区分 occurrence removal/edit 与 canonical withdrawal/correction，不能仅凭同一 source ID 推断范围。删除分支副本只失效该 occurrence、其宿主上下文和依赖该出现位置的派生引用，不建立全局 canonical 排除，不影响其他仍获授权的引用或无关分支新消息。分支编辑默认脱离旧引用形成带新身份的分支原文；只有明确授权的根来源更正/遗忘才对 canonical 来源及全部依赖执行失效。prepare、恢复和清理回执必须保留相同操作范围；分支局部操作失败也不得升级为全局删除。

安全端口必须显式提供并验证能力，不保留 `validateDispatch = () => {}` 一类默认放行。来源引用在核心保持稳定 ID，由宿主解析成可打开的原文链接；界面文案与 i18n 留宿主。

wire 协议版本、数据库 schema、文件 hash、来源版本、全局 revision、作业 generation 分开定义。远程调用需要握手、取消、超时、幂等 operation ID 和重连后的结果查询；写入超时不能当成未执行后换 ID 重试。

### 8.5 插件统一持有核心与单所有者

- **Viva、独立 DSH、dsh-web 使用相同装配。** DSH 服务端插件创建 core + Node 存储，持有唯一数据库/文件写入者、后台整理和索引任务。插件从 DSH 会话摄取，执行检索注入与记忆工具；Viva 不再逐轮提取/注入，也不创建 MemoryRuntime 或打开记忆库。多窗口、会话和 Web 连接不各自创建引擎。
- **Viva 作为宿主客户端。** 现有界面通过 Electron IPC 到后端薄适配，再通过受信进程通道调用插件 API。宿主保留自己的历史事务/outbox、任务调度、可信项目映射、原文跳转和副本清理。普通 DSH 会话由插件摄取，宿主只补来源别名、权限和它独有的历史/任务事件，不能重复提交同一回合。
- **其它 Node 宿主可直接使用独立库。** core/node 不依赖 DSH，可注入非 DSH 模型/来源端口直接运行。产品首版只维护插件持有核心这一种部署，不保留 remote-core 模式或新建常驻记忆服务；普通 Node harness 验证代码独立性，不是另一套产品部署。

DSH 不可用时，记忆服务也暂不可用；Viva 不打开备用数据库，不伪造空结果，不在后台启动另一份核心。前端显示不可用，写操作须获得持久接收回执才可显示待处理；未被插件接收的普通请求由调用者保留原 operation ID 再试。已有宿主历史变更意图仍保存在宿主 outbox，未完成核心 prepare 时不提交原历史变更、不报告完成。此时不承诺离线记忆管理；若 DSH 能在模型未配置时加载存储服务，可通过能力状态提供不需模型的操作，但 P2 须实测，不能作为默认假设。

每个真实数据根目录有进程级单写锁，重复挂载/符号路径别名不能绕过；不能仅凭 PID 复用或超时就抢活锁。启动先取得独占权、建立新 owner epoch、恢复排除/意图/任务及已绑定宿主的待撤回水位，再开放相关模型请求和对外 ready。身份相同的插件重启只恢复同一数据根，不随模型、会话或项目切换另建库。数据根由受信启动配置选择，模型和浏览器不能指定。

卸载先停止摄取/新任务、关闭发送准入、取消/排空计算并保存待办，最后关闭存储和释放锁。重启后客户端握手并重查未知结果，旧租约/回执不授权新工作，热重载不重复订阅、调度或安装 hook。正常遗忘在插件内完成屏障，不能沿用“停止 DSH 后，再调用同进程核心提交”的流程。异常终止后由新实例先恢复排除和未完成操作再发送；确认旧进程退出才释放相应发送者的不确定状态。DSH 启停/重启造成的可用性变化对 Viva 与 Web 一视同仁。

### 8.6 请求屏障与遗忘协议

核心决定是否可用，适配器负责在真实外发边界强制执行。租约绑定可信调用者、owner epoch、job generation、全局 revision、动态 readset 与有效期。前台、后台、定时、恢复、note、dream 各阶段、语义核验、工具下一轮及 SDK 每次 HTTP 重试/重定向重放均须重新准入。node_search 摘要、read 正文、工具结果和保留的推理上下文都携带依赖；新增读集同步更新截止时间，后续发送和最终提交重新核验。

遗忘先持久化排除并提升 revision，立即拒绝新读取、新发送准入与旧结果提交，再完成发送屏障并清理核心副本与宿主副本。已经发出的请求无法追回，但其迟到结果不能提交；远端提供商留存不属于本地可擦除副本。宿主历史、后台任务、定时任务载荷和恢复上下文通过持久清理命令执行；失败保持“已阻止使用、清理待完成”，不能报告彻底清理。重启、重试、撤销和迟到回执不得复活排除内容；没有可验证清理能力的宿主不能宣称已完成端到端遗忘。

发送准入与 mutation 共用串行协调协议：许可是受跟踪的在途租约，持有至 transport 明确提交请求体或确认放弃，不能拿到一次 permit 后脱离协调任意发送。适配器必须声明可观测的 transport 提交边界；多段请求体在完成前按在途处理。遗忘关闭新准入后，撤销尚未发送许可，并等待 transport 确认停止或已有发送排空；与撤销并发且已实际发送的请求记为不可追回。只有越过此 fence，才能报告“旧内容不会再从本系统外发”生效；排除持久化不等于发送 fence 已完成。取消调用返回、连接断开、许可超时都不能单独证明远端已停止。失联且未确认的许可保持待完成，恢复时阻止受影响工作；必须验证旧 transport 已停止（必要时由宿主终止其执行进程），不得由新 owner 仅凭 epoch 改变就忽略旧发送者。core 持久记录需恢复的撤销/fence 状态，适配器在重连前也不能复用旧许可。

发送许可不得仅在流开始时检查。全局 fetch/undici hook 如仍需使用，封装在 DSH 适配器，并验证多插件共存、卸载和引用计数；不能成为 core 的全局副作用。模型适配无法保证每次真实发送受控时，拒绝携带记忆依赖的路径，不静默降低屏障。此约束适用于未来非 DSH 模型适配；取消函数本身不是发送屏障。

### 8.7 独立打包和 Web 验收

`memory-dsh` 可打包安装，禁止 `../../../src` 或开发仓库路径依赖；contracts/core/node 产物随依赖安装，TS 源码进入严格类型检查，发布入口输出可运行 JS。core/node 在没有安装 DSH/Electron 的空项目中可导入并运行；DSH peer 兼容范围独立声明。验证 `npm pack` 后安装产物，不能仅凭源码测试声称插件可用；本轮不自动公开发布。

这里的 dsh-web 指 `dsh web` 浏览器产品，`@deepseek-ai/dsh-web` 包是联网 search/fetch 服务，不是该产品的接入入口。当前依赖可检查 session/llm/tools/userQuestions 及 Remote 服务接口；P2 验证插件能在实际 Web 服务端加载、接收会话并通过现有对话/工具返回结果。需要 API 时复用 DSH Connection/Remote 的身份与资源校验，不能挂无鉴权 HTTP 路由。专用管理页面及页面扩展能力后置，不是独立插件交付前提。

### 8.10 通用宿主接口与 Viva 接入细化

接口分为公开记忆服务、受信宿主协作、核心计算端口三类。公开接口不暴露 ModelCompute、原始存储、文件根路径或发送许可；模型工具只获得其授权子集。宿主客户端只依赖 `memory-contracts`，禁止 Electron IpcEvent、ACP 对象、Viva conversation/task 数据结构、DSH Agent/Context 穿过契约。以下为逻辑接口名，不要求逐项拆包或建立新服务框架。

| 接口组 | 通用操作 | 输入/输出与边界 |
| --- | --- | --- |
| 连接与能力 | `connect`、`status` | 返回协议版本、instanceEpoch、ready/recovering/unavailable、实际支持的操作/计算能力；认证由连接适配绑定，不接受客户端自报 owner 授权；版本不匹配明确拒绝 |
| 查询 | `list`、`search`、`read`、`getProfile` | 带经过绑定的授权上下文，返回不透明记忆 ID、版本、内容/命中行、来源引用、partial/不可用原因；不返回宿主路径、内部数据库对象或凭据 |
| 写入与管理 | `remember`、`revise`、`setEnabled`、`forget`、`undo`、`setProfile` | 命令携带 operationId，修改带 expectedRevision；正文来源区分用户显式输入与模型提议，后者必须经证据准入。forget 的目标及撤回范围由核心解析校验，不能借任意 source ID 清除越权内容 |
| 整理与维护 | `runDream`、`rescan`、`reindex` | 按需提供有权限的宿主入口，返回可查询 operation；不把普通模型工具变成管理命令入口。定时唤醒仍由插件内部执行 |
| 操作与最小交互 | `getOperation`、`answerClarification` | 操作返回持久接收、执行/清理待完成、完成或失败；查询和答复校验绑定权限、问题/目标版本。基础撤销入口使用返回的 revision/change ref，无需历史列表页面 |
| 来源关联与转交（受信） | `bindContext`、`linkSources`、`attachDependencies` | 将宿主命名空间下的 thread/project/message/task 引用映射到 canonical source 与 DSH 会话；只能由已认证宿主适配调用，验证实际事件映射。派生摘要/任务载荷携带核心返回的依赖引用，重新使用时校验，不能靠客户端自报“有效” |
| 宿主原文变更（受信） | `prepareSourceChange`、`commitSourceChange`、`getOperation` | 沿用 8.4 intent→prepare/fence→宿主事务→幂等收尾；操作类型明确区分 occurrence 与 canonical，prepare 票据绑定宿主、目标/版本、语义和 operationId，不允许拿一个票据修改另一来源 |
| 宿主副本清理（受信） | `pendingHostEffects`、`ackHostEffect` | 核心持久命令带 causeOperationId、effectId、版本、绑定宿主及最小来源引用；宿主幂等清理本地历史/任务副本后按版本回执。断线可拉取恢复，不靠 UI 通知保证投递；没有自有副本的宿主无需虚构清理处理器 |

**恢复期与能力协商。** connect/status/getOperation 和完成恢复所需的受信来源变更/清理回执在 recovering 阶段可调用；否则会出现“等 ready 才能清理、等清理才能 ready”的死锁。受影响的检索、计算和新业务写入仍关闭。启动配置绑定需要同步的宿主及其能力，只有该宿主可声明同步完成水位；任意连接不能冒充宿主、挂起恢复或确认清理。能力按实际功能声明：普通 DSH 对话无需 Viva 历史副本处理能力；接入了宿主历史/任务副本的路径必须具备对应清理/依赖转交能力，否则明确拒绝该路径，不能静默降低遗忘保证。

**统一命令语义。** 请求使用 requestId 做一次传输关联，operationId 标识一次领域写入；同一授权客户端/操作命名空间内，同 ID 同内容重放原结果、异文拒绝。重启后身份命名空间保持稳定，instanceEpoch 只用于旧连接/租约失效，不使写入幂等记录失效。跨进程数据为可序列化 DTO，TypeScript 用判别联合和运行时 schema 验证；本地 AbortSignal 由传输转为取消消息，不直接序列化。

查询取消即可结束等待；写入超时/取消不等于回滚，已接受普通操作仍由核心完成或持久记录终止结果；来源变更进入 preparing 后按 8.4 保持可恢复协调，不受普通取消/失败终态规则覆盖，客户端先用原 operationId 查询，不能换 ID 重发。结果区分 `accepted` 与 `completed`，遗忘另带发送屏障与副本清理进度，不能把进入队列当作已忘记。错误至少区分 unauthorized、invalid-input、revision-conflict、unavailable、protocol-mismatch、operation-id-conflict；错误带结构化参数，由宿主翻译文案。普通操作异步失败有可查询终态；来源变更则返回当前协调阶段及待恢复原因；需要重试时遵循该操作状态，不隐式另起一次修改。

**最小通知与原文链接。** Viva 可接收 `memoryChanged` / `operationChanged` 的授权失效通知，仅带版本/操作引用；通知允许合并或丢失，重连和页面重开重新查询快照，通知不承担清理命令的可靠投递。此处不新增 Web 管理订阅平台。来源返回 `{namespace, sourceId, occurrenceId}` 等稳定引用，由宿主解析定位；核心不拼 Viva 页面 URL、不直接打开文件。缺少宿主定位能力时展示已授权依据摘录，不能伪造原文链接。

**唯一摄取与注入入口。** DSH 适配器在真实用户消息可靠接收时登记来源，回合完成后才排入自动笔记任务，分别补读接收与加工进度，并注入有效记忆；Viva 普通发送链路仅附可信上下文/消息别名，不再调用 accept/recordNoteTurn 或自行拼记忆 prompt。同一条宿主消息映射至 DSH 事件后沿用同一 canonical source，显式 remember 引用该来源并按 operationId 去重。宿主特有且未经过 DSH 的手动记忆/画像使用公开命令；历史续接、后台转交和定时任务通过受信映射附带依赖，不当作新的用户证据。插件自己的 note/dream 会话不回流摄取。

本轮工具执行前必须能从受信 DSH 接收记录/pre-step 原消息取得已登记的用户原文，不能拿模型工具参数补造来源。DSH 异步 event 通知本身不能保证先后顺序，适配器须提供登记完成的等待屏障；不能可靠确认时拒绝依赖该来源的请求。取消/失败回合不冒充 completed、不自动生成笔记；已成功提交的显式 remember/forget 不因回合取消而回滚，结果按原 operationId 查询。保留可验证用户来源以支持已提交操作，未完成助手输出不升级为依据；恢复同一事件沿用来源身份与工具操作身份，不能重复写入。

**Viva 迁移位置。** `compose.ts` 仅装配连接、项目/来源映射和已有宿主 outbox；`memory-ipc.ts` 将既有 UI 操作转换为通用客户端调用，来源链接与 i18n 留此层；`memory-withdrawal.ts` 保留历史事务，改调 prepare/commit 协议；记忆 store/runtime/dispatch/embedder 和任务调度由插件创建。`memory-channel.ts` 调整为客户端传输与服务端分发的中性协议实现，不维持插件反向请求 Viva 计算/准入的旧模型；内部模型计算无需经宿主 RPC。DSH 停止时 UI 显示不可用，原文变更 outbox 留待恢复，不降级为直写记忆文件。

**阶段验收。** P1 固化契约、核心端口和来源/能力权限边界；P2 交付插件所有权、Viva 客户端替换、唯一摄取和上述生命周期/来源变更闭环；R3 补更正替代关系与修订/停用限制，R4 统一所有检索出口的适用状态，R5a 接完保留的界面动作及删除→forget 映射，R5b 做实际 Web 核心链路与最终切换。P2 必测：消息来源先登记、本轮工具再执行、completed 后才加工，同事件/操作重放不重复，Viva 管理命令绕过模型直接到插件，丢回执后重启查同一结果，旧 epoch 请求拒绝，越权受信 API 拒绝，recovering 期间可完成水位/清理握手而不开放模型请求，DSH 重启期间遗忘/历史修改不假成功，恢复先清理再发送，宿主缺少无关可选能力不阻断纯对话接入。协议兼容是调用方/服务端版本协商，不是旧数据库迁移。

### 必须落实的实施约束

1. **P2 来源先登记，不能在 pre-step 等待未来事件。** 实测观察到 inbox 事件→pre-step→正式 user/message→模型/工具；默认 profile 的 session-checkpoint-policy 在 pre-step hook 中 await sessions.flush，但观察到 flush 事件不构成不同装载顺序/自定义 profile 的持久化先后保证。插件须从受信 inbox 或 pre-step 原消息完成持久登记，建立并等待必要的来源/会话持久化屏障后才推进接收游标或放行依赖请求，再关联正式事件；区分 received/admitted/completed，后续 hook 拒绝和取消不触发笔记。插话可在 step 3 等任意后续 step 到达，不能仅处理 step 1。Viva 插话/任务的传输包装通过已认证宿主映射还原来源，不能按 `【插话】` 等文字猜测并删改用户原文。
2. **P2 fork 和派生上下文分别处理。** 固定 DSH 版本的普通 fork 保留原消息 ID，因此用已登记的 `(owner, message.id)` 关联 canonical source，校验 source.kind 与正文版本；不必仅为普通 fork 增设 parentSession。未登记继承来源、同 ID 异文不能自动当作新原文。runtime-context、skill-catalog、time-context、记忆注入和压缩摘要都不成为用户证据。标题生成有 sessionId、purpose 和先行的 `session/title-llm-request.messageSeqs`，须据此登记依赖读集，不能遗漏或当成新用户输入；压缩/恢复等其他路径仍逐项验收。
3. **P2 约束额外上传字段与每次真实发送。** 当前 DeepSeek provider 默认的 `dsh_session_log` 包含 inbox、原文及历史，messages 屏障不能覆盖它。首版支持 profile 必须将 `session-log-deepseek` 的 `config.enabled` 设为 `false`；已实测禁用后工具循环、插话与 HTTP 503 重试正常，实际 body 无该字段。插件启动能力检查和最终 transport 边界须验证此约束，无法证明则拒绝受影响路径，不能仅相信配置。`dsh_plugin_packages` 当前仅为包名/版本；新 provider/扩展字段必须审计实际数据依赖，不能默认无害。重试的完整 body 可能变化，每个真实 attempt 都重新绑定实际 payload、读集与许可；已通过的 6 项旧 HTTP dispatch 测试不能替代新 fence 的并发撤销和崩溃验收。
4. **R3 流完成与历史提交必须显式校验。** BlockAssembler 在没有终止 chunk 时也可能默认 stop；适配器记录明确 finish 事件，截断流不可提交。复用现有文件 journal，修订/替代元数据与完成回执在恢复事务中一起提交；基本撤销创建新修订，继续受目标版本、当前来源及遗忘排除约束，不回写覆盖后续修改。
5. **R4 单独设置效果门槛。** 原样使用现有 20 条事实、13 条可回答查询的诊断：纯向量 Top5 为 11/13，当前 daily BM25/RRF 为 10/13；通用英文功能词预处理探针恢复到 11/13。原因是只匹配 `the` 的词项候选把正确语义结果从第 2 挤到第 6；预处理属于通用词项规范，不是业务谓词表，若采用须记录为相对现有排名基础的变更并补回归。另两条跨语言/音译查询的正确向量排名为 15 和 11，尚未解决。R4 用独立留出集验证并分别报告召回、最终依据核验与无答案处理；不能在同一批样本上调参后声称效果通过，也不能靠扩大这个 20 条小样本的候选池掩盖缺陷。是否需要现有模型端口参与受控查询改写，须以评估决定，不预先增加独立子系统。`min_score=0` 返回相近候选不等于已有可回答依据。
6. **R5a 按行为迁移旧接口。** 现有 renderer 的 forgetMemory 是“停止使用”、reviveMemory 是恢复，deleteMemory 才是删除。薄适配明确映射为停止→`setEnabled(false)`、恢复→`setEnabled(true)`、删除→`forget`；不得按旧方法名称机械映射，也不保留旧数据库兼容语义。
