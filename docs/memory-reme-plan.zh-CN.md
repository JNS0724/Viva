# Viva 文件记忆：ReMe 行为复刻方案

[English](memory-reme-plan.md)

状态：2026-11-15，R1、R2 已实现，R3–R5 待实现。本文替代旧方案的记忆组织、加工和检索设计；原文校验、权限、遗忘和请求屏障要求继续有效。旧数据不迁移。仅实现自研版本，不接入 ReMe 服务，不修改 ReMe 对照分支。

## 1 基准与范围

唯一行为基准为 agentscope-ai/ReMe 提交 `b13034ba2ff7339bb03df4fa4ee130b47a731c6c`。升级基准必须重新记录差异。这里的“复刻”指文本会话的 Auto Memory、Auto Dream、Markdown 文件体系和搜索行为，不包含整个项目。

- **照 ReMe 做**：session → daily → digest；frontmatter、Sources、wikilink；Extract → Integrate → Finish → Auto Tag；节点搜索与片段搜索分离；Markdown AST 分块、BM25/向量 RRF、链接展开。
- **Viva 必需差异**：后端绑定权限与来源，模型文件操作经过受控适配器；有效来源和版本检查；遗忘屏障；本地向量模型；任务恢复元数据使用 SQLite。
- **暂不做**：图像、外部资源摄取、主动发现、独立原子事实库、Hindsight observations/mental models、多跳推理 agent、额外重排模型。

ReMe 已知边界也要记录：任意 Agent 文件操作不是事务；回执提交前中断可能重执行；失败输入后续扫描窗口必须包含其日期才能重试；自动标签失败不会因没有文件变化而自行重试。Viva 的持久化待办恢复属于明确的运行可靠性差异，不声称来自 ReMe。

## 2 文件与真值

每个授权范围使用独立、由后端选择的工作区根目录，模型只能看相对路径，不能选择其他 scope 根目录。

```text
session/dialog/<session-id>.jsonl
daily/YYYY-MM-DD.md
daily/YYYY-MM-DD/<name>.md
digest/personal/<name>.md
digest/procedure/<name>.md
digest/wiki/<name>.md
metadata/                  # 回执、目录版本、索引等，可恢复数据
```

Markdown 是 daily/digest 正文的权威来源；不把 digest 再拆成另一套正式事实。SQLite 管理任务、提交意图、回执、排除标识及派生索引，不维护独立记忆真值。原始作者、来源 ID、消息版本属于后端可信元数据，模型不能自行修改。

frontmatter 至少支持 name、description，并保留附加字段。daily 关联 session_id、source_conversation；标签字段为 memory_tags。可读文件名不充当会话身份；会话每日唯一性由 session ID + 日期确定。重命名要更新入链，不允许新旧路径同时被当作两张卡片。

Sources 使用完整句子说明 `[[daily/...md]]` 支持什么。digest 之间的 wikilink 融入正文。链接目标是完整 workspace-relative 路径，可有显示名和 anchor；路径不隐式补 `.md`。读工具的行号参数与路径分开。

Viva 路径边界：拒绝绝对路径、反斜杠、`.`/`..`、控制字符及符号链接穿越。正式写入只能由单个后端所有者完成。文件内容 hash 是本模块快照版本；请求屏障仍使用全局内容 revision，两者不能混用。

## 3 Auto Memory

输入：已完成回合、必要前文、消息 ID/作者/发生时间、稳定请求 ID、现有当日卡片。只处理有实际新增内容的回合。保留用户/助手区分，过滤 tool-result 和二进制负载，助手内容只能作为讨论上下文，不能伪装用户依据。

按会话与日期寻找卡片，生成或更新有复用价值的偏好、事实、决定及原因、进度、经验。不生成流水账。更新日索引，使同一天的卡片可浏览。模型建议文件名；后端解决碰撞并验证归属。

每日日期按消息时间及配置时区确定，不把恢复时间当作历史发生时间。请求 ID 相同且输入相同重放回执；相同 ID 不同输入拒绝。无值得写入内容是成功的 skip；模型失败不是 skip。

笔记保存成功后才标记该批回合完成。更新中的源版本改变时，旧结果不提交。笔记生成后可立即搜索，不等待 dream。

## 4 Auto Dream

### Extract

刷新扫描窗口中的日索引，读取相对 checkpoint 有变化的 daily Markdown。一次跨文件提取可复用抽象，不逐文件摘要。

输出契约为 `{units:[{name,bucket,summary,paths}]}`。paths 只能引用本次输入的 changed paths；bucket 为 personal/procedure/wiki，未知字符串按 ReMe 回退 wiki。同名 unit 跨批次合并来源，保留较丰富 summary。名称合并仅限当前授权范围。

正确空数组表示无可复用内容；格式失败先按上游规则纠正一次，再记录失败；请求无法承载多文件时拆批隔离。失败、未扫描和因 unit 预算延后的文件不得 checkpoint。预算与截断规则按基准实现，不擅自增加最近 N 张或返回正文开头的限制。

### Integrate

每个 unit 一个计算会话，工具限定为 node_search、read、frontmatter_read、write、edit、frontmatter_update。先查询 digest 节点摘要，再读取相关正文。分类 same_abstraction / related / unrelated。

必须选择 CREATE / CORROBORATE / REFINE / CORRECT，并且只写一个目标 digest 节点。CREATE 落到对应 bucket；更新可跨 bucket 命中已有抽象。没有 SKIP。保留已有来源和链接，补齐 unit 依据，把相关节点链接写入有上下文的句子。

模型操作先作用于隔离草稿；读取最终草稿、验证一个目标、有效来源、允许范围、预期版本后才能正式提交。原文跨度检查只能证明出处，不能证明概括正确；语义核验必须覆盖否定、时间、条件及第三方归属。不能把“需要语义核验”伪装成确定性字符串校验。无法验证则失败保留待办。

返回 `{action,target_path,note}`。后端核对回执与实际草稿写入一致。失败 unit 及来源路径留作失败；不能把“模型返回成功”当作已经落盘。

### Finish 与 Auto Tag

只有已处理且没有失败 unit 依赖的来源才能 checkpoint，保存的是本次读取版本而非完成时版本。处理期间发生修改仍留作新工作。按 ReMe 更新本轮扫描的日索引记录。

只对实际新增/修改文件打实体标签，同文件去重。打标失败不回滚已成功的整合，并单独记录；首次实现不额外发明自动标签重试策略。标签更新也经过文件版本校验。

## 5 默认值清单

来源分别为 ReMe DSH 集成配置、default.yaml、DreamExtractStep 与 SearchStep；不同入口参数不能称为 ReMe 的全局默认。

| 项目 | 本次基准值 |
| --- | --- |
| DSH 写笔记间隔 | 5 回合 |
| 集成时区与 dream 时间 | Asia/Shanghai，23:00 |
| dream 扫描日期数 / unit 上限 | 2 / 5 |
| dream 批次预算 / 文件读取上限 | 40,000 文件字节 / 60,000 Unicode 字符；超预算单文件仍单独成批，读取超限追加 truncated 标识 |
| search 默认 limit / 最大 limit | 5 / 50 |
| 每路候选 | min(200, limit × 5) |
| vector 权重 / RRF k / min_score | 0.7 / 60 / 0 |
| Markdown chunk 字节目标 | 10,000 |
| 链接展开 | 入链、出链各最多 10 |

本地向量开启是 Viva 明确选择，ReMe 默认 embedding 关闭。不得为了对齐数值而忽略单位、fallback、分页和失败语义。

## 6 搜索与索引

node_search 只查询 digest 节点的名称、描述等信号，供去重及关联发现，不自动展开正文。search 面向 daily/digest 的 FileChunk，全文和向量各自产生候选，按 ReMe RRF 融合；单路可用直接返回该路排名。分数不是概率。

Markdown AST 解析 frontmatter、标题树、列表、表格、代码块和 wikilink；chunk 保留祖先标题与实际原文行号。先按结构分块，再按预算处理过长叶节点。不能退化为只取开头字符或固定最近文件集合。

结果提供 path、start_line、end_line、正文、得分、入链/出链邻居摘要及计数。需要更多内容时 read 使用独立行号参数。空命中与同一工具上下文已返回完毕区分。去重缓存随文件版本变化失效。

启动扫描和运行时文件变更更新 FileNode/Chunk/Link、BM25 及向量。删除移除全部派生数据。按 ReMe，reindex 从已接受的 chunk 快照重建派生索引，不等同重新扫描文件；全量扫描是独立修复操作。向量空间切换后禁用旧空间查询，重建成功后恢复。

## 7 更正、遗忘与恢复（Viva 必需差异）

CORRECT 是带来源的文档修订，不自动推断“最近写入的永远正确”。普通历史保留，遗忘删除不受“只增不删来源链接”的普通整合规则限制。

遗忘先提交排除标识和 revision，立即阻止读取、模型请求及旧计算结果提交，再清理原始来源副本、daily、digest、历史和索引。混合依赖文档先失效，再由仍有效依据重建；不能把整篇笔记作为一个不可分的独立新证据复活被删内容。来源反向依赖包含内容依赖与普通关联链接，不能沿所有相关链接误删无关文档。

文件与 SQLite 无跨介质事务。正式提交采用持久化意图：记录 operation ID、源/目标预期版本、目标新 hash；写同目录临时文件并同步，原子替换后完成回执。恢复时比较实际 hash：新 hash 完成回执、旧 hash 重试、第三种 hash 标记冲突，不能盲目覆盖。多文件（例如日索引与卡片）使用可恢复计划，未完成计划不向模型暴露混合版本。临时文件不进入 watcher。

完成前崩溃测试必须覆盖意图写入、文件替换、回执与 checkpoint 各边界。单文件原子 rename 不是完整事务保证。

## 8 分层与交付

- shared：无 Node 的路径/单元/回执契约。
- backend 文档模块：frontmatter 与链接解析，纯函数；不调模型、不决定权限。
- backend 文件存储：原子文件 IO、快照版本和范围内路径边界，不判断记忆语义。
- Runtime：权限、依赖、准入、effects 调度、请求屏障及正式提交。
- 计算适配器：运行 note/extract/integrate/tag，仅返回草稿与回执。
- 搜索模块：派生索引、融合、范围与版本过滤；UI 只读后端快照。

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| R1 | 文档/路径/unit 契约、文件存储基础 | 真实文件往返、并发旧版本拒绝、路径隔离、frontmatter 保留测试；尚不启用运行时 |
| R2 | session/daily、日索引、提交意图与恢复 | 回合接入、幂等回执、重命名和崩溃恢复闭环 |
| R3 | 完整 dream 四阶段与 node_search | 四动作、一个 unit 一个目标、跨文件来源、失败不 checkpoint；移除 dream→离散提取路径 |
| R4 | AST、全文/向量、链接展开和工具返回 | 对照上游 fixtures；头尾命中、表格/代码块、重建、日期过滤 |
| R5 | UI、遗忘、请求屏障与完整验收 | 停止双读旧事实库；真实 DSH、重试恢复和删除副本测试 |

每批运行相关 TypeScript 测试和全量 typecheck；文档运行 check:i18n。切换生产运行时前运行全套测试、build 和本地 memory smoke；提交 PR 时按仓库 CI 规则验收 macOS/Windows。没有完成 R5 不宣称复刻上线。

## 9 对照测试矩阵

同会话同日期只一张卡片；同 request 重放与异文拒绝；消息时间决定日记日期；跨文件同抽象合并；四种整合动作；裸来源链接/越权写入/多目标回执拒绝；一成功一失败不跳过失败来源；模型处理期间来源修改；重命名入链更新；整合后标签失败保留正文；向量失效回退 BM25；行号与原文对应；表格/代码结构；相同工具上下文重复结果；重启恢复；遗忘时任务在途；权限隔离与请求屏障。

语义质量另用固定中文会话真实模型评估：短回答、引文、否定、条件、历史纠错、项目流程和偏好；模拟模型单元测试不能证明提取正确。

## 10 实施记录

- R1：shared 单元/回执/路径契约、frontmatter 往返、行读取和文件快照已实现。
- R2：已将已完成会话回合接到 `session/dialog/*.jsonl`，daily 正文以 Markdown 为准。SQLite 仅保存身份、来源版本、任务、待提交计划和回执。沿用 `VIVA_DAILY_MEMORY=1` 实验开关，默认运行时尚不切换；不接入 ReMe 服务。
- 范围由后端来源元数据确定，使用授权范围的 hash 隔离工作区；文件系统会话名使用 session ID 的 hash，原 ID 保存在 JSONL 和 frontmatter。消息时间与配置时区决定日期。同会话同日期只保留一张卡片，标题变更会重命名并更新入链和日索引；中文长文件名与碰撞由后端处理。
- 同请求同输入重放、异文拒绝。skip 有成功回执，模型异常或格式错误保持待办。来源版本、原文和文件 hash 都参与提交检查；助手保留独立角色，仅作为上下文。文件写成后立即进入现有 daily 搜索路径。
- 提交意图先持久化，文件替换后在同一 SQL 事务中提交回执和回合完成标记。崩溃恢复核对新/旧 hash，第三种 hash 留作冲突且隐藏整个未完成计划；失效来源或被取代的任务不提交。完成后清除计划中的正文副本。单文件层同步文件及目录（Windows 只同步文件）；正式写入仍限定为一个后端所有者，不承诺跨进程 CAS。
- 遗忘先隐藏卡片，再以持久化清理任务移除 session 副本、卡片和日索引链接；完整 digest 历史/派生索引清理、外部文件扫描和 UI 状态仍在 R4/R5 验收。
- R3–R5：待实现。dream 暂时沿用旧离散提取路径，后续由四阶段文档整合替换；不宣称整个新版记忆已完成。
- 验证覆盖真实进程在意图、文件替换、回执和 checkpoint 边界被终止，会话追加与重命名恢复、外部写入冲突、来源版本变化、重复请求、scope 隔离和模型失败。全量测试通过（具体统计见交付验证日志）；typecheck、build、check:i18n 与本地 memory 冒烟通过；memory 冒烟验证现有默认链路，新 daily 文件链路另有真实 DSH 回合集成测试。
- 上次定时查询失败：本轮全量及 8 次定向检查未复现原失败。确认并修正了断言只检查最后一条消息的缺陷，改为按调用 ID 查找 `schedule_list` / `schedule_update` 对应结果；回归覆盖工具结果后追加运行时通知、无对应调用和不同工具。旧失败缺少请求快照，不能断言该缺陷是当时唯一原因；保留失败时的定时任务列表、工具结果和末条消息诊断。

### R2 循环评审修复

三路子 agent 分别检查存储恢复、运行时和上下文回归，修复后均复审通过。没有新增谓词分类表。

- 回执完成但 effect 尚未结束时，恢复先结束旧 generation，再处理后续批次。入链卡片随重命名原子更新 hash/版本，撤回期间不恢复已失效来源。
- 清理计划使用可空的真实卡片路径及预期 hash；外部冲突仅隔离对应工作，不阻止其它工作区启动。多来源回合撤回一条后保留独立用户原文、删除派生助手内容并重建。
- 助手副本保留会话来源依赖；临时或已失效上下文不落盘。跨日短回答沿用同 workspace/session 的上一句问题。请求 ID 固定为原始完成事件，输入指纹与安全保存副本分离，撤回和重放不会创建重复回合。
- 文件模式保留 session 仍需使用的完整原文，防止旧离散提取及候选过期压缩破坏 daily 校验。note/dream 的实际正文、标题、问题与助手上下文在请求和提交时均重新校验，不把外部修改后的敏感文本发给模型。
