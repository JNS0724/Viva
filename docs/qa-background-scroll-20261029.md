# 后台运行时主对话滚动验收（2026-10-29）

固定步进滚轮阶段确认并修复了主对话任务卡的冗余重建及焦点丢失。用户补充“鼠标滚轮快速连滚”后，连续输入阶段复现了约400ms的滚动位置停顿；当前证据涉及Windows无障碍树查询，尚不能宣布用户感受到的全部卡顿已经解决。

## 场景与证据

- Windows，系统缩放175%，120Hz；应用100%，CSS视口1360×861。
- 隔离合成profile；千轮历史，主话题2000条、实际绘制不超过200条；另覆盖完整200KB Markdown的507节、约19万px文档高度。
- DeepSeek-V41-Flash HIGH真实后台输出，主对话不输出。每组16次原生往返滚轮，记录trusted事件、实际scroll位置和后台任务生命周期。覆盖后台空闲、持续输出、结束后，以及后台浮层展开。
- 基线为8f8efb3。修复候选在相同合成profile重新启动；候选文件哈希单独记录，原始SHA和失败产物保留。

## 修复内容

旧任务卡缓存依赖整个任务对象。后台每次增量文字都会产生新任务对象，即使卡片上的标题、状态和摘要没有变化，也会替换整个button。长文滚轮实际动作窗口内，主对话子节点新增/移除各163次。

缓存现按卡片实际显示的身份、标题、状态、当前动作、已用分钟数、确认/提问和结果摘要判断。后台回答继续完整更新；卡片显示不变时保留节点。显示变化仍及时刷新，点击仍进入对应任务。没有修改封存的长对话方案，没有截断正文或削弱复制、搜索和读屏。

新增真实Electron DOM回归：连续100个后台消息块，旧构建节点保留0/100且丢失焦点；修复后保留100/100、焦点和主对话节点均保持。已检查全部消息块、分钟边界、两次确认内容变化、完成摘要和两次点击入口。

最终真实后台滚动窗口内，主对话子节点新增/移除均为0。不同进程间滚动插值数量也有变化，但原因未充分隔离，不作为修复带来滚动速度提升的证明。

## 验证与限制

- 严格类型检查、构建、770/770测试通过。
- 六阶段smoke全部exit0；其中新增DOM回归实际输出retained=100、focused=true，确认/摘要/入口断言均通过。
- 最终浮层展开场景Chromium trace同时包含起止标记及全部16个wheel事件，时钟映射最大误差0.142ms，buffer39.5%，解析rejected=0。
- 第一轮后台任务在滚动前两秒报错结束，已排除。首个候选trace接近满缓冲区且缺少结束标记，不能作为完整trace覆盖；最终短录制有效。
- 普通长历史后台场景有独立WPR起止与归档哈希；系统事件解析和CPU/GPU归因尚未完成。之后一次90秒录制在展开浮层动作前结束，明确不作为动作覆盖。
- 原生固定步进滚轮不等同高频连续手势。用户已明确采用鼠标滚轮快速连滚，后续结果见下节。窗口遮挡会暂停rAF等待，相关工具等待不计作应用滚动卡顿。
- 200KB冷展开的150ms预算、完整窗口矩阵、含尺寸变化的资源趋势及安装产物验收仍未完成。本报告不是整体发布通过证明。

完整本地证据：`E:/viva/qa-20261029-performance/desktop/background-scroll-summary.json`；检查点与弱点分别在同目录上级的`CHECKPOINTS.md`、`WEAKNESSES.md`；新增回归日志为`task-card-regression-smoke.log`。
