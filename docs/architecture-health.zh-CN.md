# 架构整治：降低一次修改需要理解的范围

[English](architecture-health.md) | 简体中文

审查基线：2026-11-06，main `26e4db4`（PR #95）。这是源码与变更历史审查，不是运行性能评测。第一批保持产品行为和现有进程边界。

## 证据与优先级

产品的 `src`、`plugins` 中有 243 个 TypeScript/JavaScript 文件、30,521 行（含空行、注释和翻译，不含依赖、测试、图片、CSS）。体量本身不足以解释开发速度；更明显的问题是职责和修改集中。

| 优先级 | 证据 | 对修改的影响 | 整治方向 |
| --- | --- | --- | --- |
| P1 | `src/backend/compose.ts` 1,105 行、55 个不同的本地依赖；最近 50 个非合并提交中修改了 25 次 | 配置卡片、会话生命周期、历史切换、记忆轮询、定时与进程装配共享闭包，修改一个功能要重新理解其它功能的初始化顺序 | 让功能模块拥有业务操作和状态；入口保留创建、连接与销毁 |
| P1 | `src/renderer/app.ts` 1,103 行、43 个本地依赖；同一批提交修改了 15 次 | 页面绑定、发送与插话、卡片响应、事件分派混在一起，发送竞态只能通过整个页面排查 | 将对话副作用抽成可注入依赖的 actions；页面入口负责连接 |
| P1 | `globals.d.ts` 的 `Action`、`Untyped`、部分 IPC 返回值使用 `any`；`acp-bridge.ts` 也有开放字段 | 重构时，错拼 action 或跨模块数据形状变化可能绕过类型检查 | 先补每个功能的 action/event 联合和 IPC 结果，不一次替换全局状态类型 |
| P2 | `view/render.ts`、`view/hub.ts` 从可执行入口 `app.ts` 引入 `Dom` 类型 | 形成类型依赖回环；改页面启动会影响 view 的契约。它不是运行时循环 | 把 DOM 契约放进可独立导入、无模块级启动副作用的页面绑定模块 |
| P2 | 架构文档仍写 793 个单测，基线实际为 919；旧的重连限制也未同步 B2 | 开发者和模型会按过时描述重新调查或重复设计 | 文档描述机制，具体数量以测试输出为准；修正重连限制 |

已有值得保留的边界：shell/backend 分离，IPC 入参契约，任务状态只有 TaskRuntime 一个写入方，存储变化与事件同事务，以及 renderer 的 state/actions/view 分层。整治应沿用它们，不另建第二套任务调度或状态权威。

## 第一批已经落地的边界

- `src/renderer/conversation-actions.ts`：普通问题、图片、插话、轮次结束后的重送、反问和凭据响应。只依赖窄 API、状态访问、dispatch 和 UI 回调；不依赖 `document` 或 `app.ts`。
- `src/renderer/page-elements.ts`：一次绑定页面元素并导出 `Dom` 类型。view 不再反向依赖应用入口。
- `src/backend/config-actions.ts`：模型通过已批准的卡片执行 MCP/技能操作。依赖配置存储、技能根目录、回收站能力和变更回调；不依赖后端启动或 ACP 进程。准备卡片不写存储，成功写入后才标记 MCP 需要重载。
- `test/module-boundaries.test.ts`：遍历 `src` 和 `plugins` 的 TypeScript/JavaScript 源码，扫描真实语法树（含类型导入、重导出和字面量动态导入），禁止功能模块导入应用组装入口，并拒绝源码依赖环。现有后端/Electron 边界检查继续保留。

入口的行数变为 `compose.ts` 1,041、`app.ts` 943。总文件数会增加，工厂装配也仍需导入各功能；这些不是优化目标。实质是发送竞态和配置操作可以在独立测试中验证，修改它们不再需要导入启动整个应用的入口。

新增行为测试覆盖：轮次刚结束时插话改走下一问、多个插话只重送一次、失败消息保留、错误后清除待重送内容、图片发送限制、问题/凭据的 request id、凭据不进页面状态、配置预检查无写入、密钥仍加密、修改失败不触发重载、导入与技能回收。

## 第二批：dsh 生命周期

`src/backend/dsh-lifecycle.ts` 已接管运行实例、generation、重启计时器、崩溃记录和退出标记。创建和连接通过窄能力注入；配置、历史、任务状态和事件路由留在各自原模块。启动、停止和故障恢复不再共享组装入口里的可写运行变量。

契约测试覆盖：并发启动只连接一次、停止在途启动、旧代事件与退出、真实释放完成后才替换、1/3/10 秒崩溃退避与放弃、取消已排队重启、退出标记、启动失败清理、释放失败阻止替换，以及退出等待超时仍保留释放屏障。就绪回调在当前代校验后执行，取消的连接不能发布旧 ready。

这一批包含可验证的竞态修正：停止在途启动时撤销结果；初始化失败时释放实例；并发启动合并；退出超时不放开资源屏障。实例退场还会明确结清正在运行的前台轮，避免旧事件被过滤后，新实例仍被视为忙碌；取消时清除排队的插话重送，标记未送达消息，并撤销在途 idle 回执。真实 dsh 的生命周期冒烟在反问等待中更换模型和清除 key，随后验证新话题和后台结果回报；换 key 时先结清旧话题，再创建新话题。迟到记忆采集仅在原话题仍为当前话题、且没有新前台轮运行时继续，绑定已结束轮次的话题和会话；此保护不为记忆存储增加会话级来源归属。它不改变 IPC、数据库格式或 TaskRuntime 的状态权威。历史和工作目录会话切换的独立所有者见下一节。

## 话题与工作目录选择

`src/backend/conversation-session.ts` 拥有当前历史段、工作目录、一次性携带记录和待完成的会话切换。`compose.ts` 注入存储、运行实例和展示信息的能力，不再写这些会话变量，也不再实现模型匹配、新话题创建、目录分叉和恢复失败处理。

历史和重来命令必须通过选择回调执行：准入闸门覆盖运行会话切换、历史写入和段落选定，包括同一 session id 的不同历史段。新运行会话已经创建、但模型匹配失败时，继续阻止提问和回报，直到成功重试或明确完成状态核对；仅凭缓存信息不能断定运行实例还在旧会话。历史元数据保存不能清除此闸门。每次切换退出都会唤醒等待的效果队列；已知未改变会话的分叉失败会让回报在原对话继续。

针对性契约使用真实的内存历史库、效果队列和历史/重来 IPC 处理器，覆盖并发新话题、失败与重试、精确恢复和恢复信息、已保存/空白前置段的目录分叉、旧运行实例的迟到结果、一次性记录、延后回报和选择提交。它们不代替完整应用冒烟及双平台 CI。

对话推送现在携带提问或插件请求开始时捕获的历史段和运行会话。renderer 在启动初始化和选择 RPC 提交期间缓存前台推送，随后按接收顺序、保留原接收时间，仅重放所选上下文的消息；后台任务流保持实时。这修复了后台结果立即回报、却早于新话题 RPC 响应到达页面时的丢失窗口。反问和凭据关闭保留原请求归属；迟到的提问失败与插话回执不能影响新选话题。重来时先处理缓存的报告，再决定自动追问应走新提问还是插话。实际事件映射还补全了后台权限关闭，不虚构用户决定。离线目录切换也发布所提交的历史段。MCP 重载经同一所有者核对冷启动替换后的 session，并在释放排队回报前发布配置；目录、重来和设置切换期间拒绝新发送。事件解码与可穷举 action 的所有者见下一节。

## renderer 的事件与 action 契约

`agent-events.ts` 拥有未知输入边界、选择缓存、任务读取交接及推送触发的副作用。`agent-event-decoder.ts` 把各类受支持载荷投影为闭合的 `AgentEvent` 联合，丢弃未使用的 ACP 数据，在 reducer 或文件/动态副作用之前拒绝未知和异常帧；诊断仅包含已知标签及原因。`agent-event-actions.ts` 可穷举地映射已验证事件，后台片段分别保留 run id、任务序号及全局事件序号的语义。旧的新话题标签筛选已删除入口。

全局 `Action` 现为有限载荷表生成的联合，处理器按标签取得对应载荷，不再接受开放字典。对话状态、文本/思考流、工具、过程记录、等待和回执均有明确类型，排除在旧状态类型扩宽工具之外。后台审批和反问响应使用独立 action 标签；前台载荷不能夹带后台路由字段。会话元数据和对话 IPC 返回值已贯通类型。其他功能载荷仍引用原有状态契约，这不代表所有旧功能数据都已完整定型。

生产入口测试覆盖启动重放、缺省配置字段保留身份与恢复状态、SDK 审批可空字段的工具回退、任务读取期间真实 TaskRuntime 的快照/片段交接、任务与全局序号分离、异常定时提案，以及被拒绝帧不会触发副作用或带出原始载荷。所有受支持标签均有样本；仅编译的负例拒绝拼错 action、缺少文本/任务标记及混合前后台身份。全量测试和双平台冒烟仍是必要闸门。

## ACP 操作与后台会话所有者

`acp-operations.ts` 拥有原生提问身份、捕获的上下文、流结算和取消期限。前后台共用此机制，不共享可写操作记录。每次 await 后核对操作身份；旧操作不能结束或删除同一原生 session 的下一次操作。释放会撤销未完成的流绑定，并阻止新工作进入。

`acp-task-sessions.ts` 拥有后台原生会话的附着集合、已知配置值和无人值守标记，通过窄 transport、权限、反问、插话及只读能力创建、恢复、配置、提问、取消和关闭后台会话。在异步获取之前捕获前台目录和配置，包含 SDK boolean 选项。配置或只读标记失败会释放尚未发布的会话；释放后迟到的获取不能重新附着。每个原生附着还带私有请求身份：关闭撤销在途恢复，旧配置/标记回调不能删除新附着，重新附着需等待前一次关闭及等待清理完成。bridge 保留进程、MCP 预备、前台选择和资源关闭屏障，不再写后台附着、无人值守或 running Map。TaskRuntime 继续独占准入、应用轮次、状态、事务、持久化和报告。

所有者契约覆盖不返回的取消 RPC、复用 session 后迟到结果及 finally、流绑定和原生会话获取期间释放、配置快照、boolean 请求，以及配置/只读标记失败清理。既有公开 bridge、流、恢复、资源屏障及 TaskRuntime 测试继续验证实际接线与行为。

## 测试反馈与退役入口

`npm run test:feature -- conversation` 执行对话契约（包含事件入口、核心 reducer 和凭据）以及共享 IPC、页面 API 和模块边界检查。其他人工维护的分组是 `runtime`、`tasks` 和 `architecture`；多个分组会去重，`--list` 展示所选文件。运行时组包含 keeper 和桌面反问，任务组包含提议状态。分组用于本地反馈，不是自动的传递依赖分析。未知名称或空组会在启动前失败，子测试退出码原样传回。发现入口同时包含 `.test.js` 和 `.test.ts`，跳过已安装依赖和符号链接，通过参数数组启动 Electron，不经过 shell。脚本纳入类型检查；测试覆盖混合发现、目录循环、非法选择及跨功能代表契约。完整 `npm test` 和 coverage 的发现方式不变。

无人调用的 `openConversation` 页面 API、`history:open` 参数契约/处理器和 `conversation_opened` action/handler 一并删除。源码搜索确认没有产品调用方：回顾经 `history:read` 读取，继续话题或撤销新话题经 `history:resume-topic`，从记录恢复仍经 `history:continue-from-records`。历史测试改走现行路径，不再制造退役的 open action。真实数据库测试保留保存、删除、撤销、搜索和导出，并验证阅读旧历史不能切换所选 agent。会话不可用、目录缺失、忙碌、携带记录及拒绝迟到加载的契约仍保留。

## 本轮范围与交付标准

| 顺序 | 范围 | 完成条件 |
| --- | --- | --- |
| 2 | dsh 生命周期及话题/目录选择 | 分别由独立模块拥有进程生命周期和所选会话状态；契约验证失败恢复与切换期间的回报，完整冒烟和双平台 CI 仍为最终闸门 |
| 3 | renderer 的事件入口和对话 action 类型 | 用可穷举联合表示收到的事件和对应 action；未知事件在边界明确处理；只改前台事件不必改后台任务 reducer；保留“新话题准备中丢弃旧前台推送”测试 |
| 4 | ACP 主对话与后台会话的内部职责 | 先明确两者共用的 transport、权限和取消能力，再抽会话控制；保持进程所有权、任务运行准入和 TaskRuntime 单写入，不复制状态机 |
| 5 | 测试反馈与依赖清理 | 提供按功能执行的短反馈路径；全量及两端冒烟保持最终闸门；删除确实没有调用方的旧接口，保留契约与故障测试 |

每批只改一个可解释的职责，先确定状态由谁拥有，再移动行为及其测试，最后删除旧入口。文件拆小或改扩展名不能单独作为完成依据。第一批未修改 IPC、数据库格式、任务生命周期或 ACP 语义；后续这些边界如需改变，应单独评审和验证。

## 怎么判断是否变快

基线本地完整测试：919 项通过，约 14.8 秒（本机、现有依赖、一次测量）。这不包含两平台 CI 的机器排队、依赖安装、构建、打包和冒烟；等待远程 CI 与源码理解成本要分别记录。

每批记录四项：一次代表性功能修改涉及哪些模块、入口是否仍承载该功能的业务逻辑、针对性测试耗时、完整检查结果。本轮清理后，本机一次对话分组实测为 239 项通过、约 1.1 秒，使用现有依赖；这不是对产品速度或开发提速比例的保证。先按所改职责获得快速反馈，再执行完整闸门：

```sh
npm run test:feature -- conversation
npm run test:feature -- runtime tasks --list
npm run typecheck
npm test
```

最终验收继续运行 `npm test`、`npm run check:i18n`；重大架构改动先本地 build 和完整 smoke，再看 PR 当前提交的 macOS/Windows CI。没有完成同类修改的前后对照前，不承诺开发速度提升百分比。
