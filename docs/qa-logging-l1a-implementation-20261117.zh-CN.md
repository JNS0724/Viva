# L1a 日志首批实施记录

日期：2026-11-17。分支：`codex/local-diagnostics`，基线：`84c16d3`。开发位于独立 worktree，原开发目录及其中的测试工程改造未被修改。本记录是实施自检，不代表新增运行时代码已经获得独立子 agent 的全面评审。

## 实现范围

已实现可移植非抛出诊断端口、Node 上下文环绕、Pino 10.4.0 / SonicBoom 4.2.1、白名单与身份别名、有界排队与写入、文件配额与串行轮转，以及 Yazl 3.3.1 独立子进程 ZIP 导出。

记忆读取的五个阶段由实际 owner 请求的 wait 事件记录阶段、requestId、epoch 和耗时；保留进程边界 span，移除同一代理链的重复包装。dream 提供计算、解析/校验、重试、不可用与证据过期的区分。发送屏障记录实际 transport 的开始与 settlement，取消仍不代表已经结算。DSH 只观察公开接口，Viva 和独立 Web 验收 profile 关闭遥测上传。

本轮修复并覆盖了日志关闭早于配额回执、轮转期间退出丢失已准入队列、文件打开失败后库定时 flush 使用无效句柄、小尾部没有后续事件就不落盘、大 RPC 为诊断复制完整 body、迟到 owner 回包无记录、Renderer 限流没有计数、错误分类触发业务 getter、DSH 观察回调异常影响工具执行、owner 初始化失败泄漏日志句柄等问题。

导出范围固定后发生的后续写入不属于该 ZIP。实机测试先观察异步日志批次已经落盘，再暂停测试自己的 Backend 和 Renderer；不等待 memory:get 返回。原生菜单仍能生成 ZIP，并确认包含 Renderer 记录、manifest，且不包含测试资料的原始路径。

## 最后一轮固定交错 A/B

使用 Electron 44.7.0 内置 Node 24.21.0，在同一台 macOS 机器运行生产 HTTP、实际 owner IPC 和独立 Node owner 的 SQLite/文件读取入口。owner 为空数据集；不开模型、不引入人为模型等待。每模式 500 次，交错 100 轮，每轮每模式 5 次。20ms 请求间隔位于计时之外。启停日志时逐次比较业务结果完全一致。

复现命令：`ELECTRON_RUN_AS_NODE=1 node_modules/.bin/electron scripts/benchmark-memory-diagnostics.ts`。

P95 增加 **0.426792ms / 13.0762%**。主进程日志队列峰值 **491520 字节**，owner 峰值 **327680 字节**；两侧丢弃均为 **0**，测量结束排队与活动 span 均为 0。最大写入确认延迟分别为 11.983291ms、13.674125ms。

**性能未通过方案第 13 节的原始门槛（增幅不超过 5%，且绝对增加不超过 10ms）。没有修改门槛，也没有将失败标成通过。** L1a 因此尚未完成全部验收。按侧线程评估，停止继续扩大微优化范围，保留证据；没有加入额外日志 Worker、采样子系统或扩大业务改造。

该样本没有覆盖有数据 owner、Renderer IPC 与渲染、完整 DSH 应用、Windows 或安装包。不同修订的基线曾在约 2.35–3.75ms 之间变化，不能用跨运行百分比证明优化收益。旧修订的 context-only 试验曾增加约 0.275ms；它只能说明当时成本不全在 Pino 落盘，不能作为当前版本的性能下限。
