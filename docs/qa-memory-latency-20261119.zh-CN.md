# 记忆检索延迟验收 · 2026-11-19

在 Apple M4 的 macOS arm64 上使用 Electron 44.7.0（Node v24.21.0），运行 Viva 的 ACP 桥接、本机 DSH、独立 memory owner 和嵌入子进程。模型由本地 HTTP 夹具给出确定的回复。文件经正常的记忆写入接口发布，首轮测量前确认向量索引已激活。8 和 96 个文件两组使用同一个目标文件、查询和工具次序。96 文件组另外开启日记以准备 Dream 输入。

```sh
npx --no-install cross-env ELECTRON_RUN_AS_NODE=1 electron scripts/benchmark-memory-latency.ts
```

结果写到 `smoke/memory-latency.json`。可用 `--samples=24 --cold=12 --catalog=96` 指定样本数和较大文件集的规模。每个工具样本在一轮内执行「召回 → 按 ID 读取 → 节点搜索 → 再次召回」。每轮使用新会话。冷组每次重启 DSH 和 owner，保留已发布索引与操作系统文件缓存。

召回与节点搜索 p95 均低于 300 毫秒，读取 p95 均低于 100 毫秒。96 文件组的正常召回始终命中固定文件，并返回 `candidate-limit`，说明候选排序受限。向量故障由嵌入子进程收到指定查询后退出触发。两组首次故障召回分别用时 16.13 和 20.88 毫秒，均返回目标及 `semantic-unavailable`。同回合的再次召回耗尽已返回的匹配结果时，回执为 `exhausted`。

Dream 使用真实的日记输入和手动触发接口。测量期间扣住本地模型返回给 Dream 的抽取回复，首尾均验证 Dream 状态为运行中。释放回复后，验证 Dream 完成处理并写入持久化进度。

单独计量从本地模型发出工具调用到下一次收到含工具结果的模型请求。它还覆盖模型流结束、转录持久化和下一次请求准入。96 文件组在该边界下，热读取 p95 为 198.18 毫秒，冷读取为 245.75 毫秒，冷组再次召回为 367.49 毫秒。这段等待仍会反映到用户看到后续回答的时间。

## 自动注入与启动

交替运行真实检索和短路对照，每组各 24 对。对照提交一段被记忆敏感模式判定为应跳过检索的合成文本。计时从父进程注册输入开始，到本地模型收到首个带记忆工具的请求为止。逐对相减后计算分位数。

| 文件数 | 自动注入首个模型请求 p50 / p95 | 短路对照 p50 / p95 | 配对增加等待 p50 / p95 | 命中证据 |
| ---: | ---: | ---: | ---: | ---: |
| 8 | 45.81 / 52.06 | 32.10 / 37.97 | 13.48 / 20.66 | 24/24 |
| 96 | 57.50 / 74.67 | 42.62 / 56.53 | 5.35 / 37.56 | 24/24 |

配对增加等待的 p95 均低于 100 毫秒。两组冷启动到桥接就绪的 p50 / p95 分别为 734.83 / 1197.20 和 710.16 / 768.36 毫秒。冷组每项 12 次，p95 取该组最大值。

本轮数据用于检验本地链路延迟与故障降级。嵌入模型使用确定性向量夹具，Dream 并发主要覆盖等待模型的阶段。工具结果已经核对目标内容。真实模型和嵌入质量、Windows、旧版本对照，以及逐请求目录扫描、文件核验和 IPC 次数无本轮实测数据。
